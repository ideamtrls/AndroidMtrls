# Collections

Primitives that take a list of items, own the gesture/animation choreography of moving through it, and emit events or write hoisted state — visual mechanics stay in the primitive, MEANING stays with the caller.

## Shared contract

All generic components take `items: List<T>` + `key: (T) -> Any` (stable identity; the Compose translation of iOS `id: KeyPath`). Content arrives via a trailing `@Composable (T) -> Unit` slot. CardStack and Carousel impose **no framing** on slot content — callers wrap in `AMCard` / `amElevation` themselves; ChipGroup and Tabs apply fixed chrome around their slots by design.

Two output styles: **emit an event** (`AMCardStack.onSwipe`) or **hoisted state** (`currentIndex`/`onIndexChange`, `selection`/`onSelectionChange`) — the caller owns the state and must write it back or the component never advances. `AMPageIndicator` is read-only.

Tunables (`sideInset`, `spacing`) are `Dp? = null`, falling back to `LocalAMTokens` (`spacing.lg` 16dp, `spacing.md` 12dp, `spacing.sm` 8dp). Motion tokens used here: `modalSpring` (stiffness 224, dampingRatio 0.86 — mirrored as file-private `modalSpringDp = spring<Dp>` in PageIndicator.kt), `snapSpring` (stiffness 384, dampingRatio 0.86 — mirrored as file-private `snapSpringDp = spring<Dp>` in Tabs.kt per the conventions.md lockstep rule), `selectionFade` (150ms tween, EaseInOut). Press feedback is the `amRipple()` state layer, not a motion token.

Every animated spec here is reduce-motion-aware via `tokens.motion.resolved`/`resolvedOrNull` (`tokens/Motion.kt`, keyed on `LocalAMReduceMotion`): fades and gesture-completion moves (CardStack snap-back/depth, PageIndicator dot, Tabs label + content fade) SOFTEN to the overlay-fade tween via `resolved`, while the Tabs underline slide COLLAPSES via `resolvedOrNull` (snap). The Carousel's RM policy is different because its gesture physics are the platform pager's: a programmatic index change uses `scrollToPage` (instant) under RM instead of `animateScrollToPage`; user-drag settles are native pager snaps and are not RM-modified. The CardStack fling is the one motion RM *removes* rather than softens: a committed card fades out in place (no cross-screen translation) instead of flinging. Gestures still land in the correct end state under RM — motion is collapsed, behavior is not; the 1:1 drag tracking (`snapTo` per pointer move) stays instant.

**Pure-math extraction:** hand-rolled gesture/layout algorithms live in Compose-free `internal` files so JVM unit tests cover them without an emulator — `CardStackMath.kt` (tilt, commit decision, exit targets, depth scale/offset/alpha), `FlowMath.kt` (`amComputeFlowLayout` + plain `AMFlowItemSize`/`AMFlowPosition`/`AMFlowLayoutResult` carriers — deliberately not `IntSize`, to keep the test classpath Compose-free). The composables delegate every calculation to these functions. Tuning constants stay private in the composable files; the math functions accept them as parameters whose defaults match the constants value-for-value. Tests: `mtrls/src/test/kotlin/**/collections/{CardStackMathTest,FlowMathTest}.kt`. The Carousel has no math file — its gesture physics belong to the platform pager (see its section).

CardStack drag handling follows the house pointerInput rules (plain-`var` accumulators, hoisted `MutableInteractionSource` lists keyed on `items.size`) — see conventions.md. End-of-drag velocity comes from `androidx.compose.ui.input.pointer.util.VelocityTracker`; the projected landing point is `predicted = offset + velocity * AM_FLING_PROJECTION_SECONDS` where `AM_FLING_PROJECTION_SECONDS = 0.499f` (defined in CardStackMath.kt) — the WWDC-2018 UIScrollView projection with `decelerationRate.normal = 0.998` (`velocity × decel/(1000·(1−decel))`), an effective ~0.5s window (iOS's `predictedEndTranslation` is the twin). A linear projection is used rather than `splineBasedDecay` deliberately: the spline needs a `Density`/Compose runtime, which would break the Compose-free JVM math-test classpath.

NOTE: there is **no reorderable list** in `collections/` — reorderable list variants live in `lists/` (see `lists.md`).

## AMCardStack (CardStack.kt + CardStackMath.kt)

Tinder-style deck. `AMCardStack(items, key, visibleDepth = 3, onSwipe, modifier, content)`. Renders `items.take(max(1, visibleDepth))`; empty list renders nothing (caller owns the empty state). Z-order is draw order — the loop runs `lastIndex downTo 0` inside a `Box` so the top card composes last. **Requires an explicit height from the caller** (`Modifier.height(…)`); width fills internally. Root semantics: `contentDescription = "Card stack, card 1 of $total"`, plus the root captures its measured width via `onSizeChanged` (for the a11y swipe below).

Depth styling per step (math in CardStackMath, applied in `graphicsLayer`): scale `0.96^depth`, translationY `8dp × depth × density`, alpha `0.72^depth`. Scale, alpha, **and the y-offset** all animate via `animateFloatAsState` with `stackSettleSpring` (stiffness 224, dampingRatio 0.82) so a promoted card glides up smoothly — all three animate together. The composable captures `density` from `LocalDensity` for the animated y-offset target.

**a11y (`AMSwipeDirection` custom actions):** the top card exposes TalkBack `CustomAccessibilityAction`s "Swipe left"/"Swipe right" that call the same commit path a released drag takes, with zero velocity — flinging (or RM-fading) from the measured root width. So the deck is fully operable without the drag gesture (iOS `accessibilityAction(named:)`).

Per-fling constants are deliberately **not tokenized** — the stack's physicality is tuned as one piece and must not drift under theme overrides:
- Tilt clamps at **±12°** (`MAX_TILT_DEGREES`), reaching max at `0.5 × width` of drag; `amCardStackRotationForDx` returns 0 for width ≤ 0.
- Commit on release if `|dx| > 0.25 × width` **OR** `|dx + vx×0.499| > 0.6 × width` (`amCardStackShouldCommit` — the velocity arm, using the shared `AM_FLING_PROJECTION_SECONDS` window, lets a quick flick commit on a short drag).
- Exit targets (`amCardStackExitTargets`): `exitDx = ±1.6 × width`; `exitDy = dy + (dy + vy×0.499) × 0.3` so the exit follows the finger's diagonal.
- Motion: `flingAnimation` = `tween(280ms, LinearOutSlowInEasing)` (ease-out, not spring — the card is leaving and must not overshoot back); `snapBackSpring` = spring(320, 0.78) (rejection, slightly bouncier). There is **no** fling-settle delay constant — see the join contract below.

The commit choreography is one shared local `launchCommit(itemKey, direction, exitDx, exitDy)` used by both the drag gesture and the a11y actions. Under **Reduce Motion** it fades the committed card out in place (a shared `fadeAlpha` Animatable 1→0, tagged by `fadingOutKey`, on the RM-softened depth spring) instead of flinging across the screen — the large translation is exactly what RM removes. Otherwise it flings `dragOffsetX/Y` to the exit targets. Either way the report fires the moment the exit animation completes — the fling `animateTo`s are joined (`x.join(); y.join()`), not a fixed delay, so it self-adjusts to the real (possibly RM-softened) duration.

GOTCHA — the key-tagging trick: only the card whose `key(item)` equals `draggingKey` reads the two shared `Animatable`s (`dragOffsetX/Y`) and the tilt; the card tagged by `fadingOutKey` reads `fadeAlpha`. `draggingKey` is set at drag start (or by the a11y action); when the exit animation completes, `onSwipe(item, AMSwipeDirection.LEFT/RIGHT)` fires and **the caller must remove the item from its own state** — once it leaves `items`, no rendered card matches the key, so the new top renders at rest with no reset-in-lockstep dance; `draggingKey`/`fadingOutKey` are then nulled and the animatables `snapTo`. The report **re-reads** `items.firstOrNull()` at completion time — both `items` and `onSwipe` are tracked through `rememberUpdatedState`, so the long-lived per-card `pointerInput(itemKey)`/`launchCommit` closures never freeze the composition-time values — and only invokes `onSwipe` if its key still equals the flung `itemKey`; a deck mutated externally mid-fling drops the stale report (iOS `report(topID:)` guard). A per-pointerInput `gestureGeneration` counter guards a new drag starting mid-snap-back spring from having its `draggingKey` cleared by the old gesture's coroutine; `onDragCancel` snap-backs the same way. Direction semantics (skip/save/etc.) are entirely the caller's.

## AMCarousel (Carousel.kt)

Horizontal pager with peek-of-neighbors, built on Compose Foundation's **`HorizontalPager`** — the gesture, fling, and snap physics are the platform-native ones (a fling advances at most one page). `AMCarousel(items, key, currentIndex, onIndexChange, sideInset = null, spacing = null, modifier, content)`; empty list renders nothing; `currentIndex` is clamped internally so a briefly out-of-range value is safe.

Geometry comes entirely from pager parameters: `contentPadding = PaddingValues(horizontal = sideInset)` (page width = container − 2×sideInset, neighbors peek through the padding), `pageSpacing = spacing`, `verticalAlignment = Alignment.Top` (the pager default is CenterVertically, which would shift short content). `sideInset` default `spacing.lg`, `spacing` default `spacing.md`. The pager constrains each page's width — slot roots must not set their own width. Item identity flows through the pager's `key = { key(items[it]) }` parameter. GOTCHA — the pager **clips to its bounds** (scrollable-container clipping): peek only paints inside the composable's own width. A caller wanting the peek to bleed to an edge must widen the carousel itself (see the demo home band, which uses `requiredWidth` + `offset` for an asymmetric flush-left/bleed-right band).

**Two-way index sync (equality-guarded on both sides so the directions can't loop; precedent: SwipeActions.kt):** `rememberPagerState(initialPage = clampedIndex) { items.size }` owns the scroll position.
- **Pager → caller:** a `LaunchedEffect(pagerState)` collects `snapshotFlow { pagerState.currentPage }` and calls `onIndexChange(page)` when it diverges from the clamped index. The collector reads `clampedIndex`/`onIndexChange` via `rememberUpdatedState` — long-lived gesture-adjacent closures must never capture composition locals directly (stale-capture rule). `currentPage` flips **mid-gesture** once a drag crosses the halfway point, so `onIndexChange` can fire before the finger lifts (not only at release).
- **Caller → pager:** `LaunchedEffect(clampedIndex)` scrolls the pager when the controlled index diverges — `animateScrollToPage`, or `scrollToPage` (instant) under Reduce Motion — and is **skipped while `isScrollInProgress`** so a programmatic write never fights an in-flight drag; the settle report reconciles any divergence afterwards.

The a11y semantics sit on the pager's modifier: `stateDescription = "Page X of N"` (mirroring `AMPageIndicator`) plus "Next page"/"Previous page" `CustomAccessibilityAction`s that write `onIndexChange((clampedIndex ± 1).coerceIn(0, lastIndex))` — the adjustable-element analog of iOS `accessibilityAdjustableAction`. Pairs with `AMPageIndicator` on the same index state. The iOS twin `IMCarousel` shares this API shape and the signature look, but the two implementations deliberately keep their own platform's paging feel.

## AMChipGroup (ChipGroup.kt + FlowMath.kt)

Wrapping flow of selectable **capsule** chips (iOS filter-chip look), multi-select via `selection: Set<Any>` of keys + `onSelectionChange(updatedSet)` — tap toggles membership (the component computes `selection ± k` and hands it back). `spacing` default `spacing.sm` (8dp), used both between chips and between rows. Two overloads per the slot pattern: String convenience (`items, key, label, selection, onSelectionChange, spacing?, modifier`) and designated composable-slot (`…, chipLabel` trailing). The String overload renders `AMTheme.Type.label` text and **animates its color** `Text.primary` ↔ `Color.White` (white-on-accent) on selection via `animateColorAsState`/`selectionColorFade`, routed through `resolved`. The slot overload's **label color is the caller's job** (no content-color CompositionLocal — same rationale as the `role` rule in conventions.md): use `Color.White` for a selected chip and `Text.primary` otherwise (the caller can read the same `selection` set).

Chip chrome is fixed in both overloads: a `Row` (height **32dp**, horizontal padding **12dp**, `verticalAlignment = Center`), shape `RoundedCornerShape(50)` (**full capsule/pill**, sharing iOS's `Capsule` and the system's capsule vocabulary — AMPageIndicator, tags). **Unselected:** `AMTheme.neutralFill()` (monochrome 8% grey) fill, **no outline**. **Selected:** solid `tokens.semantic.accent.resolve(isDark)` fill with **white** label text, **no outline, no check glyph**. The fill crossfades neutral ↔ accent via `animateColorAsState` on the file-private `selectionColorFade` (a `tween<Color>` lockstep mirror of `Motion.selectionFade`, since `animateColorAsState` needs `AnimationSpec<Color>`), routed through `resolved`. Press feedback: the monochrome `amRipple()` state layer clipped to the capsule `chipShape`. Interaction sources hoisted `remember(items.size) { List(…) }`.

Wrapping is the private `AMFlowLayout` — a custom `Layout` that measures each child **unconstrained in width and free of any inherited `minHeight` floor** (`minWidth = 0, minHeight = 0, maxWidth = Int.MAX_VALUE`, the analog of iOS `sizeThatFits(.unspecified)` — a tight incoming `minHeight` would otherwise stretch every chip to a full-height slab; `maxHeight` stays inherited), converts placeables to `AMFlowItemSize`, and delegates to `amComputeFlowLayout(itemSizes, constraints.maxWidth, spacingPx)`. The algorithm (FlowMath.kt) is greedy left-to-right: `projectedWidth = rowWidth + spacing + itemWidth` (or just itemWidth on an empty row); overflow commits the row **only when the row is non-empty**, so an item individually wider than maxWidth still gets its own row — never skipped. Row height = tallest item; `totalHeight` = Σ row heights + spacing×(rows−1); `totalWidth` = max row width; positions are top-leading pixel coordinates. Empty input → zero-size result.

## AMPageIndicator (PageIndicator.kt)

Read-only dot strip: `AMPageIndicator(count, currentIndex, modifier)`. No state writing, no gestures. `Row(spacedBy(spacing.sm))` of capsule `Box`es. Active dot = **18×6dp**; inactive = 6×6dp; strip height never changes (only width elongates). Active fill `AMTheme.Text.primary`; inactive `AMTheme.Text.secondary.copy(alpha = 0.35f)`. Width animates via `animateDpAsState` with the file-private `modalSpringDp` (spring<Dp>, stiffness 224, dampingRatio 0.86 — lockstep mirror of `modalSpring`, the house page-scale motion). When paired with `AMCarousel`, the dot starts moving as soon as the pager reports the new page (mid-gesture, at the halfway point) and settles on its own spring while the pager finishes its native snap. Index clamped to `0 until count`; `count = 0` renders an empty strip. Merged semantics: `"Page ${clamped + 1} of ${max(count, 1)}"`.

GOTCHA: the active fill is **hardcoded to Text.primary** — never the accent. Callers wanting accent-colored dots build their own.

## AMTabs (Tabs.kt)

**In-page** content switcher (tab strip + cross-fading content area) — explicitly NOT a screen-level tab bar. `AMTabs(tabs: List<AMTab<T>>, selection: T, onSelectionChange, modifier)` where `T : Any`. Empty `tabs` renders nothing; a selection matching no tab falls back to index 0 for the indicator (`indexOfFirst(...).coerceAtLeast(0)`).

`AMTab<T>` is an `@Immutable` data class: `id` (matched against `selection`), `label: String = ""` (string path — strip applies the file-level `AMTabLabelStyle` (`AMTheme.Type.label`)), `labelContent: (@Composable () -> Unit)? = null` (custom path — caller owns font; the cell's `amRipple()` state layer supplies press feedback), and `content: @Composable () -> Unit` stored as a lambda so **only the selected tab's content ever runs** (the iOS lazy-closure trick). Never call `content` outside AMTabs.

Layout: outer `Column` wrapped as **one continuous flat rounded panel** — `.clip(amSquircle(tokens.radius.lg))` (16dp) + `.background(Surface.primary)` + dark-mode-only `amCardHairline` (the analog of iOS `RoundedRectangle(radius.lg).fill(Surface.primary)` + `.clipShape`; no elevation, so it reads flat, not a lifted card; the clip keeps the strip hairline off the rounded corners). Strip cells are equal-weight (`Modifier.weight(1f)`) tappable Boxes padded `spacing.md` vertically; labels use `AMTheme.Type.label`, color animating `Text.primary` ↔ `Text.secondary` on `selectionFade` (150ms, EaseInOut); press is the `amRipple()` state layer clipped to the cell rectangle, via hoisted `remember(tabs.size)` interaction sources. A density-clamped `amHairlineWidth()` `separator` line runs the row's bottom edge (`align(BottomStart)`).

Indicator: a **full-cell-width, 1dp-high** Text.primary capsule bar (`RoundedCornerShape(50)`), overlaid at BottomStart on top of the hairline. It spans the whole equal-weight cell (`cellWidth = maxWidth / tabs.size` from `BoxWithConstraints`) and is slid by `offset = cellWidth × selectedIndex` — the iOS full-width 1pt underline, NOT a Material label-width indicator. Width is fixed (`cellWidth`), so only the offset `animateDpAsState(snapSpringDp)`s; it initialises at target on the first frame, so no measure-gate or grow-in is needed.

Content area: `AnimatedContent(targetState = selection)` with a **stationary crossfade** — `transitionSpec` is `fadeIn(fadeSpec) togetherWith fadeOut(fadeSpec)`, no directional slide (iOS content "settles just behind the underline, not travel like a surface"). `fadeSpec` is a **280ms FastOutSlowInEasing** tween (the analog of iOS contentSwapSpring, response 0.28) via `resolvedFinite`; under Reduce Motion it softens to the overlay fade (still a crossfade).
