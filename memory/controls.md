# Controls

Buttons, text inputs, and pickers — split into `buttons/`, `inputs/`, `pickers/` purely for navigability; every file is "something you poke." Package root: `io.github.jmsdnns.androidmtrls.controls`.

Cross-cutting facts (beyond `conventions.md`, which owns the prefix/param-order/enabled/role/ripple-press-feedback rules):

- **Most control ROWS are flat widgets** — picker/slider/stepper rows draw NO fill, shadow, hairline, or outline of their own. The canonical wrap is a **bare `AMCard` (no `padding:` arg)** so a row lands at the standard 64dp rhythm; a padded card double-counts insets. Self-chromed controls draw their own container: the filled buttons, `AMActionGridButton`, the FAB, **the four filled text inputs** (`AMTextField`/`AMSecureField`/`AMTextEditor`/`AMSearchField` — a neutral-fill box via internal `AMFilledField`, 56dp min height, own bottom indicator), `AMStepper`'s two square tonal ± buttons, and `AMSegmentedControl`'s outlined segmented group.
- **Shared row recipe** (DatePickerRow, ColorPicker, ToggleRow, MenuPicker, Slider, Stepper): `fillMaxWidth` + `heightIn(min = AMTheme.rowMinHeight.dp /* 64dp */)` + padding `horizontal = tokens.spacing.lg, vertical = tokens.spacing.md`; leading label in `Modifier.weight(1f)`; trailing control. House headline label = `AMTheme.Type.title` `AMTheme.Text.primary`.
- **Foreground precedence** (buttons): `!enabled` → `AMTheme.Icon.disabled`; `role == AMButtonRole.Destructive` → `AMTheme.destructive`; else `Text.primary`. `AMIconButton` adds `!active` → `Icon.muted` between disabled and primary. `AMActionGridButton` PREPENDS `active && enabled` → resolved `semantic.accent` at the top of the cascade.
- **`AMButtonRole` is DECLARED in `surfaces/frames/Toolbar.kt`**, not in controls — import it, never redeclare. `AMToolbarButton` (36dp filled round chip) also lives there.
- **Press feedback is uniform across every control: `indication = amRipple()`** (the monochrome state layer from `tokens/Ripple.kt`) on the `clickable`/`toggleable`, paired with a hoisted `remember { MutableInteractionSource() }`. Bounded ripples require the affordance `Modifier.clip(shape)`'d to its visual shape so the sweep honors the AM corner radius; icon-sized targets clip to `CircleShape`. No control dims its content on press.
- **Picker motion is reduce-motion-aware:** `AMToggleRow`'s thumb geometry (position + diameter), its ON check-glyph fade, AND its colour cross-fades all route through `tokens.motion.resolved` (SOFTEN to the overlay-fade tween under Reduce Motion — the thumb slides but never snaps). `AMSegmentedControl` marks selection with a tonal-fill cross-fade plus a leading check glyph, NOT a travelling thumb: the fill routes through `resolved(selectionColorFade)` and the check's fade through `resolvedFinite(selectionFadeFloat)` (both soften), while the check's horizontal expand is a spatial shift so it routes through `resolvedFiniteOrNull(selectionExpand) ?: snap()` and SNAPS under Reduce Motion. The four filled text inputs animate their bottom indicator + floating label through the same resolvers (see `AMFilledField`). All keyed on `LocalAMReduceMotion` (`tokens/Motion.kt`). The remaining pickers (`AMStepper`/`AMSlider`/`AMMenuPicker`/`AMDatePickerRow`/`AMColorPicker`) animate nothing, so they need no routing.
- Param-naming deviations to know: `AMCardButton` and `AMFloatingActionButton` use **`accessibilityLabel: String`** (iOS name carried into the API), not `contentDescription`. `AMCardButton` and `AMFloatingActionButton` take **no `modifier` param** at all.

## Buttons (`controls/buttons/`)

### `AMPrimaryButton` / `AMSecondaryButton` / `AMGhostButton` (Buttons.kt)
Primary and Secondary share private `AMFilledButtonBody`: `fillMaxWidth` + `defaultMinSize(minHeight = AMTheme.rowMinHeight.dp /* 64dp */)`, `amSquircle(tokens.radius.md)`, `Surface.primary` fill, `amCardHairline(shape)` (selectionRing stroke, **dark mode only**), `amElevation(AMElevation.Low)`, `semantics { role = Role.Button }`. Press = `amRipple()` bounded to the clipped card shape (the frame is `clip(shape)`'d before the fill, so the sweep respects the `radius.md` corners). The frame Box sets `contentAlignment = Center` — that is what vertically centers the label row inside the 64dp min-height frame (the row's own `verticalAlignment` only centers within the row). Label row padding: vertical `spacing.md`, horizontal `spacing.lg`, centered.
- **All three String labels are one 17sp size, weight-only variation** (the pair's shared signature look renders all three at one body size, differing by weight alone). The file-level `amButtonLabelStyle(foreground, weight)` helper derives the style from the `body` token (`AMTheme.Type.body.toTextStyle(color).copy(fontSize = 17.sp, fontWeight = …)`) so color/tracking flow from the token; the 17sp size (`AM_BUTTON_LABEL_SIZE`) is a deliberate literal, NOT a Type token (tokens/Type.kt untouched — this is a documented exception to the "emphasis is Medium, never SemiBold" scale rule, since primary renders SemiBold). Weights: **primary `FontWeight.SemiBold`, secondary `FontWeight.Normal`, ghost `FontWeight.Medium`** (iOS `.semibold`/`.regular`/`.medium`). Slot overloads are byte-identical pass-throughs to the body — slot content is caller-styled (no content-color local; destructive slot callers use `AMTheme.Semantic.destructive`).
- Ghost: bare `Row`, no fill/elevation/hairline; press = `amRipple()` bounded to a `amSquircle(radius.sm)` clipped around the label row (ghost has no fill, so the clip only gives the sweep a sane bound); padding vertical `spacing.sm` / horizontal `spacing.md`; String label 17sp `FontWeight.Medium` (see above).
- Slot overloads: `(onClick, modifier, enabled, content: RowScope)`. String overloads: `(label, onClick, modifier, enabled, role: AMButtonRole? = null)`.

### `AMFormActions` (FormActions.kt)
The paired action row that closes a form sheet — a pure composition of the filled buttons with no chrome of its own. Two overloads, both String-only (they only wire the String button overloads, so there is no content slot and no `role` param of its own) and both carrying a `padding(top = spacing.sm)` inset so the row lifts off the fields above it (drop it in as the last element of a form column):
- **Create mode** `(primaryLabel, primaryEnabled = true, modifier, onPrimary)`: a single full-width `AMPrimaryButton` (the filled button already fills width), padding applied via `modifier.padding(top = spacing.sm)`. No `Row` wrapper.
- **Edit mode** `(destructiveLabel, primaryLabel, primaryEnabled = true, modifier, onDestructive, onPrimary)`: `Row(fillMaxWidth, Arrangement.spacedBy(spacing.md), padding(top = spacing.sm))` with a leading `AMSecondaryButton(role = AMButtonRole.Destructive)` + trailing `AMPrimaryButton`, BOTH `Modifier.weight(1f)` for equal widths. The destructive label tint comes entirely from the String overload's `role` (label renders `AMTheme.destructive`).
- **`primaryEnabled: Boolean = true`** is the house `enabled` inversion of iOS `primaryDisabled: Bool = false`. It gates ONLY the primary commit button; the destructive button is always enabled.

### `AMCardButton` (CardButton.kt)
Compact icon-first action button for card bottom action rows. Two overloads: slot `(accessibilityLabel, onClick, content: RowScope)` — row spacing `Spacing.xs`, press = `amRipple()` bounded to a `amSquircle(radius.sm)` clipped around the icon-and-count row — and convenience `(icon, label: String? = null, active: Boolean = false, activeTint: Color? = null, accessibilityLabel, onClick)`: icon 16dp; label 12sp `AMTheme.Type.caption` with **`fontFeatureSettings = "tnum"` ONLY — tabular digits on the default font, NOT `FontFamily.Monospace`** (iOS `.monospacedDigit()` keeps the system font; a full monospace family would put text labels like "Reply" in a code typeface). No `enabled` param. No fill/shadow — the surrounding `AMCard` supplies them. Semantics: `contentDescription = accessibilityLabel` on the row + `role = Role.Button` on the `clickable` (iOS `IMCardButton` is a SwiftUI `Button` carrying the `isButton` trait).
- **Active / foreground (convenience overload):** foreground = `active` ? (`activeTint ?: LocalAMTokens.current.semantic.info`) : `Icon.muted`, applied to BOTH the icon tint and the count text. `active` wins the whole precedence — there is no disabled state and the `amRipple()` press sweep is orthogonal to foreground (the iOS twin `IMCardButton` likewise has no disabled/pressed color branch here). Callers pass `AMTheme.Semantic.destructive` (filled-heart like) or `AMTheme.Semantic.success` (repost) as `activeTint`; a `null` tint resolves against the LIVE `semantic.info` so per-subtree token overrides flow through.
- **`active`/`activeTint` live ONLY on the convenience overload; the slot overload omits them.** Slot content is caller-styled and `:mtrls` has no content-color CompositionLocal, so the body cannot recolor arbitrary slot children — the same rule that keeps `role` off slot overloads (precedent `AMActionGridButton`, whose slot overload only draws its active ring and leaves label tinting to the caller). The slot KDoc points callers at coloring their own content with a semantic tint for a toggled-on look.
- **Hard layout rule (system-wide):** card action rows are one single row — the `AMCardActionRow` container (below) encodes it so call sites can't drift; count-labeled buttons cluster LEFT, icon-only RIGHT, `Spacer(Modifier.weight(1f))` between; share before ellipsis; ellipsis always last.

### `AMCardActionRow` (CardActionRow.kt)
The hard-rule container for a card's bottom action row — `(modifier, content: RowScope.() -> Unit)`, a pure composition with no chrome (the surrounding `AMCard` supplies fill/elevation). It fixes the arrangement so call sites can't drift: `Row(horizontalArrangement = spacedBy(tokens.spacing.xl), verticalAlignment = CenterVertically)` with a top inset. Content is a `RowScope` slot, so callers drop count-labeled `AMCardButton`s leading, the mandatory `Spacer(Modifier.weight(1f))`, then icon-only buttons trailing (share before overflow; overflow last) — the same arrangement the `AMCardButton` KDoc mandates. The iOS twin is `IMCardActionRow`.
- **Top inset is a file-level `private val CARD_ACTION_ROW_TOP_INSET = 2.dp`, DELIBERATELY not a spacing token** — the fixed 2dp lift off the content above is part of the hard design rule and a theme spacing override must not distort it (the iOS twin likewise keeps its `topInset` a private constant). It is applied as `modifier.padding(top = …)` after the caller modifier. The inter-button `spacing.xl`, by contrast, IS the live `LocalAMTokens.current` token so it flows with theme overrides (the iOS twin makes the same split — a token for the HStack spacing, a hardcoded `2` for the inset).

### `AMActionGridButton` (ActionGridButton.kt)
Action-grid tile: fixed **76dp height** (`actionGridTileHeight`), `amSquircle(tokens.radius.lg)`, `Surface.primary` fill, **`amHairline` UNCONDITIONAL — drawn in light AND dark mode** (unlike the filled buttons' dark-only `amCardHairline`), `amElevation(elevation)` with `elevation: AMElevation = Low` — pass `AMElevation.None` for grids where per-tile shadows stack into noise (catalog root does). Press: `amRipple()` bounded to the clipped `radius.lg` tile shape. Slot overload `(active, enabled, contentDescription /* required — no visible title to merge */, elevation, onClick, content: BoxScope)`; content slot is centered with 6dp horizontal inset. Convenience `(icon, title, role, active, enabled, elevation, onClick)`: 22dp icon (matches `AMIconButtonSize.Medium` glyph) above 12sp single-line ellipsized caption, gap 6dp (deliberately off the spacing grid — 4dp crowds, 8dp breaks the compact read); `contentDescription = title`.
- **Active selection ring** (`active: Boolean = false`, in the config group; iOS `IMActionGridButton.active`). `active = true` overlays a second `amHairline(shape, color = accent, width = AMTheme.selectionRingWidth.dp /* 1.5dp */)` where `accent = LocalAMTokens.current.semantic.accent.resolve(isDark)` (monochrome Black/White; flows with the demo dynamic-accent toggle — NOT the gray `selectionRing`, NOT `Text.primary`). The ring modifier sits BEFORE the base `amHairline` in the chain so it draws LAST (on top of the gray hairline); `amHairline` strokes INSIDE bounds (SwiftUI `strokeBorder`), so the 1.5dp ring never clips against the tile's `clip(shape)` — no border-inside variant needed. The **convenience overload** also tints icon+caption with the accent (foreground precedence prepends `active && enabled → accent`). The **slot overload** only draws the ring — `:mtrls` has no content-color local, so slot callers tint their own content with the resolved accent.

### `AMActionGrid` / `AMActionGridRow` (ActionGrid.kt)
The bottom-anchored FAB-menu layout you fill an `AMActionsOverlay` (or a scene's floating-actions menu) with — the two containers that stack `AMActionGridButton` tiles. Pure layout, no chrome of their own; the tiles ride at their **default `AMElevation.Low`** and self-card, floating free over the overlay's blurred backdrop (the overlay is NOT a sheet, so nothing forces `elevation = None`). The iOS twins are `IMActionGrid`/`IMActionGridRow`.
- **`AMActionGrid(modifier, content: ColumnScope.() -> Unit)`** = outer `Column(Modifier.fillMaxSize().then(modifier))` → `Spacer(Modifier.weight(1f))` FIRST, then an inner `Column(fillMaxWidth, verticalArrangement = spacedBy(spacing.md))` padded `horizontal = spacing.lg` + `bottom = spacing.xxl` (32dp — clears the gesture-nav zone). The iOS twin arranges its `VStack` the same way. **`fillMaxSize` is baked in** so the weighted spacer bottom-anchors the rows within `AMActionsOverlay`'s full-screen content Box; the grid therefore needs a **bounded parent** (the overlay supplies one) — an unbounded parent (e.g. a `verticalScroll` column) would feed the spacer infinite height and crash on measure. `then(modifier)` lets a caller composing the grid outside an overlay re-constrain it.
- **`AMActionGridRow`** = three explicit overloads taking **exactly 2, 3, or 4** `@Composable () -> Unit` tile lambdas (`tileA, tileB[, tileC[, tileD]], modifier`), each tile wrapped in `Box(Modifier.weight(1f))` inside a `Row(modifier.fillMaxWidth(), horizontalArrangement = spacedBy(spacing.md))`. The arity is enforced **structurally** — no 1-tile and no vararg/list path, so a lone tile does not compile (the iOS twin `IMActionGridRow` uses the same exact-arity inits). `modifier` is applied BEFORE `.fillMaxWidth()`, so a caller `padding(horizontal = …)` insets the whole row (used where a lone row sits outside an `AMActionGrid`'s own `spacing.lg` inset). Named args (`AMActionGridRow(modifier = …, tileA = …, …)`) disambiguate the overloads since tiles are lambdas and `modifier` is typed `Modifier`.
- Demo: `ActionsOverlayPage`'s overlayContent is the canonical `AMActionGrid { AMActionGridRow(3 tiles) }`; `ActionButtonsPage` demos the row at each legal width (2/3/4) plus a single-select active-ring filter row.

### `AMFloatingActionButton` (FloatingActionButton.kt)
56dp **circle** — `CircleShape` (file-level `AMFabShape`, shared by the fill, hairline, ripple clip, and shadow silhouette; the iOS twin uses `Circle()`), **icon LOCKED to `Icons.Rounded.Add` at 22dp** (FAB = "add"; anything else → `AMIconButton`). `Surface.primary` fill + `amHairline(AMFabShape)`. Signature: `(alignment: AMFABAlignment = Center, offset: MutableState<Offset>? = null, accessibilityLabel, onClick)` — no modifier param. `AMFABAlignment` enum (default **Center**): `Leading`/`Center`/`Trailing` → `CenterStart`/`Center`/`CenterEnd` inside a fillMaxWidth Box padded horizontal `spacing.xl` (24dp), **flush at the bottom — NO built-in bottom inset** (the hub's `bottomInset` owns any lift); callers add their own `navigationBarsPadding()` outside so the FAB clears the system nav bar.
- **Always draggable — no static mode.** Every FAB wires the tap / long-press-lift / drag gesture. `offset` is a nullable `MutableState<Offset>` for the PERSISTED drop position (px displacement from anchor, committed on lift release): pass a caller-owned state and commits write back so the position survives remounts; leave it `null` (default) and the drag is still fully live, backed by an unconditionally-`remember`ed internal `mutableStateOf(Offset.Zero)` (`internalOffset`; `dragOffset = offset ?: internalOffset`) that resets across remounts. Hoist a persisted `offset` to the scene root with `rememberSaveable`, because the FAB is conditionally removed when overlays open and internal state would snap position back on remount. The MutableState API (not value/onValueChange) is deliberate: commits originate inside the gesture coroutine. **The FAB has no `clickable` and no `enabled` param** — a11y is `role = Role.Button` + `contentDescription` on the drawn-circle node (the iOS twin uses `.accessibilityAddTraits(.isButton)`; with no semantics `onClick` action, TalkBack double-tap does not fire the gesture). Consumer disabled-state comes from the hub's alpha-dim + click-gate, not the bare button.
- **Z-order contract: content < FAB < overlay.** The FAB has no built-in top-layer escape (Compose `zIndex` only reorders siblings within one parent) — callers compose the FAB (or its container) as the last child of the scene root, or lift its container with `Modifier.zIndex`, so a dragged FAB never slides under scene content (precedent: FabPage's demo zone carries `zIndex(1f)` to beat the caption that follows it). Overlay hosts wrap the scene as `hostContent`, so overlay chrome/content always draw above the FAB.
- **Drag gesture (one `pointerInput(Unit)` `awaitPointerEventScope` loop, ALWAYS wired):** a `remember { MutableInteractionSource() }` drives the ripple. On Press → emit `PressInteraction.Press(downChange.position)` into the source (so the `amRipple()` sweep — attached via `Modifier.indication(interactionSource, amRipple())` — plays on tap even though the FAB has no `clickable`) and launch a 300ms `delay` job; on elapse `isLifted = true` + `view.performHapticFeedback(HapticFeedbackConstants.LONG_PRESS)`. While lifted, Move events assign `liveDrag` directly (mutableStateOf, NO animation, so the circle tracks the finger). Release → emit `PressInteraction.Release`; after lift → `dragOffset.value += dragAccum` + `HapticFeedbackConstants.GESTURE_END` on the committed drop; release before lift with travel `< 10.dp` slop (`hypot`) → `onClick()`. Cancel/unknown/no-change events emit `PressInteraction.Cancel` and set a `gestureCancelled` flag — neither onClick nor commit fires and the accumulated drag is discarded. Accumulators (`dragAccum`, `liftJob`, `press`, flags) are plain `var`s/vals per house rule. The loop reaches the latest `onClick` and the resolved drag-offset `MutableState` through `rememberUpdatedState` holders (`currentOnClick`/`currentDragOffset`) — the `pointerInput(Unit)` loop never restarts, so a direct capture would freeze onClick at its first value and commit drops to the wrong store on a null→hoisted `offset` flip; the layout `.offset {}` still reads the resolved `dragOffset` directly since the modifier rebuilds each recomposition. Both haptic constants are fine on minSdk 31.
- **`dragAccum` accumulates `change.positionChange()` deltas — NEVER absolute `change.position − downPos`.** The node itself moves with `liveDrag`, so absolute math in node-local coordinates feeds the applied offset back into the next reading and the FAB oscillates between finger and anchor ("sputter"). `positionChange()` localizes current and previous positions with the node's transform at dispatch, so the node's own movement cancels out. (iOS gets away with absolute math because its `DragGesture` uses `.global` coordinates.) This rule applies to ANY self-moving drag target.
- **Lift animation:** `spring(dampingRatio = 0.82f, stiffness = 503f)` (the dp/Float conversion of iOS `spring(response: 0.28, dampingFraction: 0.82)`; stiffness = (2π/0.28)²) drives scale 1.0→1.15, shadow opacity 0.15→0.35, blur 8→20dp, y-offset 2→10dp. When `isLifted` is false (resting, or drag not yet promoted) the button holds the resting values.
- **Shadow is a custom single-layer `drawBehind` + `BlurMaskFilter`** via `paint.asFrameworkPaint()` (the deprecation is suppressed — no stable alternative) — NOT `amElevation`, because the two-layer recipe doesn't expose animatable opacity/blur/y floats. The silhouette is `canvas.drawCircle(center = size/2, radius = size.minDimension/2)`, matching the circular body. Color must be set on the framework paint so the alpha reaches the mask filter. The `clip(AMFabShape)` sits before the fill so the bounded ripple honors the circle.
- **Scene use → `AMFloatingActionsHost` (in `surfaces/overlays/FloatingActions.kt`), not the bare button.** The hub wraps a whole scene once, floats this button, presents an `AMActionGrid` `menu` via `AMActionsOverlay`, and fades the button out (+ gates its click) whenever any overlay is up via the `LocalAMOverlayActive` signal every host provides. Both the hub and the bare button default `alignment = Center`. The hub adds an `enabled` disabled state (whole-view dim, since this button exposes no glyph-tint hook) that the bare button lacks. See `surfaces.md` → *AMFloatingActionsHost + LocalAMOverlayActive*.

### `AMIconButton` (IconButton.kt)
Icon-only, no chrome. `AMIconButtonSize` enum (`tapSize`/`glyphSize` Floats in dp): `Small` 32/16, `Medium` 44/22 (default, HIG minimum), `Large` 56/28. Signature: `(icon, size, active = true, enabled = true, badge: AMBadgeContent? = null, badgeTint: Color? = null, contentDescription /* required */, onClick)`.
- `active = false` → glyph in `Icon.muted`, **still tappable** (toggle-off marker: shuffle off); `enabled = false` → `Icon.disabled`.
- **The `clickable` stays wired in every state**, taking `enabled = enabled` + `role = Role.Button` (never dropped via `Modifier.then`). When `!enabled` the clickable emits `role = Button` + the `disabled()` semantics so TalkBack announces it as a disabled button (iOS `.disabled()` propagates the disabled trait) instead of the node vanishing from the tree — and a disabled clickable fires no press interaction, so neither the `amRipple()` sweep nor `onClick` runs.
- Press = `amRipple()` bounded to the tap-target circle (the Box is `clip(CircleShape)`'d so the ripple reads as a disc).
- **Badge anchors to the glyph corner, not the tap-target frame:** the glyph sits inside `AMBadgedBox` (from `content/`) which sizes to the glyph. `badgeTint = null` defaults to resolved `Text.primary` (state markers — repeat-one, shuffle-on — where red reads as error); pass `AMTheme.destructive` explicitly for notification counts.
- Semantics: `contentDescription` + `role = Role.Button` + disabled state live on the outer tap-target Box's `clickable`; the inner `Image` has `contentDescription = null`.

## Inputs (`controls/inputs/`)

### `AMFilledField` / `amInputRowClickable` / drawn glyphs (InputRow.kt, InputGlyphs.kt — internal)
`AMFilledField(placeholder, text, isFocused, shape, interactionSource, onTap, modifier, alwaysHairline = false, showIndicator = true, fieldAlignTop = false, minHeight = 56.dp, maxHeight = Unspecified, fieldVerticalPadding = 0.dp, leading, trailing, field)` is the shared filled-container scaffold behind ALL four text inputs. It draws the Android filled anatomy on the mtrls surface: an **opaque `AMTheme.Surface.primary` container** (white light / black dark) clipped to `shape` with a hairline — `amCardHairline(shape)` (dark-only) by default, unconditional `amHairline(shape)` when `alwaysHairline` (the search pill, which has no indicator to delineate it on white surfaces) — an optional animated **bottom indicator** (drawn when `showIndicator`), the muted placeholder overlay, and optional `leading`/`trailing` affordances around the caller-supplied bare `field` (a `BasicTextField` owning its own IME wiring). **No label machinery — the Mtrls UI labels inputs externally with a standing `AMFieldLabel` above the field.** Field min height 56dp (`FIELD_MIN_HEIGHT`); horizontal inset = `AMTheme.Input.inset.dp` (14dp, token-driven — the same inset `AMFieldLabel` pads with, so a standing label aligns over the field text). `contentAlignment` centers single-line content (`CenterStart`) and top-aligns the editor (`fieldAlignTop → TopStart`).
- **Bottom indicator:** a full-width bottom line — 1dp `AMTheme.separator` when unfocused, thickening to 2dp in the live `semantic.accent` when `isFocused`. Colour cross-fades on `resolved(fieldIndicatorColorSpec)`; thickness snaps under Reduce Motion (`resolvedOrNull(fieldIndicatorThicknessSpec) ?: snap()`).
- **Placeholder rule:** shown whenever `text` is empty. Drawn muted (`Icon.muted`, `AMTheme.Type.body`).
- **Shapes (all plain `RoundedCornerShape`, deliberately NOT `amSquircle`):** `amFilledFieldShape` (4dp top corners, square bottom — the single-line fields), `amFilledEditorShape` (all four corners 4dp — the editor), `amSearchFieldShape` (`RoundedCornerShape(percent = 50)` capsule — search).
- `amInputRowClickable(interactionSource, onTap)` = a no-indication (`indication = null`) full-container tap-to-focus `clickable`; a text field's tap surface is not a button affordance, so it must NOT show the `amRipple()` sweep. Nested clear/reveal `AMIconButton`s consume their own taps first.
- **Drawn input glyphs (InputGlyphs.kt):** two `internal val` `ImageVector`s — `AMInputEyeGlyph` / `AMInputEyeSlashGlyph` (`eye.fill` / `eye.slash.fill`) — hand-authored from SVG path strings via `PathParser().parsePathString(d).toNodes()` + `ImageVector.Builder.addPath(pathFillType = EvenOdd, fill = SolidColor(Black))`, no `material-icons-extended` dependency (same zero-dep precedent as the Canvas minus bar in `AMStepper`). `EvenOdd` knocks out the eye's interior so the host surface shows through (the SF-Symbol `.fill` look). Both are drawn solid black and recolored by the consuming `AMIconButton(active = false)` → `ColorFilter.tint(Icon.muted)`, the muted icon tone. The trailing clear button uses core's `Icons.Filled.Close` directly, so it needs no drawn glyph.

### The `TextFieldValue` realign pattern (TextField, SearchField, SecureField)
Each field keeps internal caret/selection state alongside the caller's plain-String binding:
```kotlin
var fieldValue by rememberSaveable(stateSaver = TextFieldValue.Saver) {
    mutableStateOf(TextFieldValue(text = value, selection = TextRange(value.length)))
}
if (fieldValue.text != value) {          // inline compare-and-set, runs in composition
    fieldValue = TextFieldValue(text = value, selection = TextRange(value.length))
}
```
Typing updates `fieldValue` then calls `onValueChange(newFieldValue.text)` (selection preserved); a programmatic `value` change realigns with the caret at end. **The trailing clear button is gated on `fieldValue.text.isNotEmpty()`, not `value`**, to avoid a one-frame desync. All three pass a bare `BasicTextField` (`AMTheme.Type.body`, `cursorBrush = SolidColor(Text.primary)`, `singleLine = true`, NO `decorationBox`) into `AMFilledField`, which draws the fill, bottom indicator, and muted placeholder around it; `isFocused` comes from each field's `onFocusChanged` (SearchField passes `isFocused = false` — no indicator). Autofocus = `LaunchedEffect(Unit) { if (autofocus) focusRequester.requestFocus() }`.

### `AMTextField` (TextField.kt)
`(value, onValueChange, placeholder /* required */, keyboardType = Text, capitalization = Sentences, autoCorrect = true, imeAction = Default, autofocus = false, caretAtStart = false, onSubmit = {}, modifier)`. A bare `BasicTextField` hosted in `AMFilledField(shape = amFilledFieldShape)`: the white `Surface.primary` container (56dp min height, `Input.inset` inset), the animated 1dp→2dp accent bottom indicator, vertically-centered text. **No `label` param — label a field with a standing `AMFieldLabel` above it** (the Mtrls labeling pattern). `keyboardActions = KeyboardActions(onAny = { onSubmit() })` — Return submits but keeps the keyboard up (iOS `resignOnReturn = false`). Trailing clear button = `AMIconButton(Icons.Filled.Close, Small, active = false, "Clear") { onValueChange("") }`, shown while `isFocused && fieldValue.text.isNotEmpty()`.
- **Caret-at-start** (counterpart of the iOS UITextField bridge): only effective with `autofocus = true` and pre-filled text. A one-shot `remember { mutableStateOf(caretAtStart && autofocus && value.isNotEmpty()) }` flag is consumed in `onFocusChanged` → `fieldValue.copy(selection = TextRange(0))`.
- Smart quotes/dashes cannot be disabled at the Android IME level — known gap vs iOS, documented in the KDoc.
- **Placeholder gating (inside `AMFilledField`, on the passed `fieldValue.text`):** shown whenever the field is empty. `AMSecureField`/`AMSearchField` gate identically.

### `AMSearchField` (SearchField.kt)
`(value, onValueChange, placeholder = "Search", autofocus = false, onSubmit = {}, modifier)` — **no `onCancel` param and no Cancel button**. A 56dp-tall **pill** — `AMFilledField(shape = amSearchFieldShape /* RoundedCornerShape(percent = 50) */, alwaysHairline = true, showIndicator = false, isFocused = false)`: the white `Surface.primary` fill with an **unconditional `amHairline` outline** (a white pill needs delineation on white surfaces) and NO bottom indicator (search bars don't label themselves). Fixed keyboard config: Text / `KeyboardCapitalization.None` / autocorrect off / `ImeAction.Search`; `onSearch` → `onSubmit()` then `focusManager.clearFocus()` + `keyboardController?.hide()` (iOS `resignOnReturn = true` — Search dismisses the keyboard).
- **Static leading magnifier:** a decorative `Icons.Rounded.Search` (20dp `AMSearchGlyphSize`, `Icon.muted`, plain `Image`) passed as `AMFilledField`'s `leading` slot; no tap target, never swaps.
- **Trailing clear button:** `AMIconButton(Icons.Filled.Close, Small, active = false, "Clear")`, shown whenever `fieldValue.text.isNotEmpty()` — clears text only. To reset a search, host-side back/dismiss handling (or this clear) blanks the query; the field has no Cancel affordance.
- **Tap scope:** tap-to-focus is wired via `AMFilledField`'s `amInputRowClickable`; the nested clear button consumes its own tap first. Previews are unfocused-only (the focused state can't be triggered statically).

### `AMSecureField` (SecureField.kt)
`(value, onValueChange, placeholder = "Password", autofocus = false, showRevealButton = true, onSubmit = {}, modifier)`. Same filled anatomy as `AMTextField` (`AMFilledField(shape = amFilledFieldShape)` — white `Surface.primary` fill, 1dp→2dp accent indicator, empty-gated placeholder; no label of its own). Keyboard: `Password` / no caps / no autocorrect / `ImeAction.Done`; `onDone` → `onSubmit()` then `focusManager.clearFocus()` (iOS `resignOnReturn = true` — Done dismisses the keyboard). Masking via `PasswordVisualTransformation` while `isRevealed == false`. **Neither the secret nor the reveal state survives process death, by design:** both `isRevealed` AND the internal `fieldValue` `TextFieldValue` are plain `remember` (NOT `rememberSaveable`), so the cleartext password never lands in the Activity saved-instance Bundle (which persists to disk) and the field re-conceals on restore. Selection is carried by `fieldValue`, so the caret does not jump when the transformation flips.
- **Reveal glyph is a drawn EYE, not a lock:** `AMIconButton(if (isRevealed) AMInputEyeSlashGlyph else AMInputEyeGlyph, Small, active = false, "Hide/Show password")` — `eye.fill` concealed ("Show password"), `eye.slash.fill` revealed ("Hide password"), tinted `Icon.muted`, always visible. `showRevealButton = false` falls back to a trailing `Icons.Filled.Close` clear button while focused with text.

### `AMTextEditor` (TextEditor.kt)
Multiline; plain-String `BasicTextField` (no TextFieldValue — caret placement is a single-line concern). `(value, onValueChange, placeholder = "", minHeight = 100.dp, maxHeight = 240.dp, autofocus = false, modifier)`. Hosted in `AMFilledField(shape = amFilledEditorShape /* all four corners 4dp */, fieldAlignTop = true, minHeight, maxHeight, fieldVerticalPadding = Spacing.sm)`: a white `Surface.primary` block with the same 1dp→2dp accent bottom indicator as the single-line fields (no label of its own), but an all-rounded block silhouette (a text block reads better without a bottom-heavy shape). Auto-grows between `minHeight`/`maxHeight`; the inner field has `verticalScroll` so content scrolls past the cap. `autofocus` uses the same `LaunchedEffect(Unit) { if (autofocus) focusRequester.requestFocus() }` one-liner as the other three fields. Placeholder shown when `value.isEmpty()`.

### `AMFieldLabel` (FieldLabel.kt)
`(text: String, modifier)` — the standing micro-label, THE Mtrls labeling pattern for inputs: labels are external to fields, so every text input and label-less control (`AMTextField`/`AMSecureField`/`AMTextEditor`, `AMSegmentedControl`; `AMSearchField` never labels) pairs with an `AMFieldLabel` above it (the iOS twin pairs `IMFieldLabel` over a field the same way, e.g. `CalendarSheets`). Renders `AMSectionHeader(text)` (uppercase 12sp Medium) inside a `fillMaxWidth()` leading-aligned `Box` padded `horizontal = AMTheme.Input.inset.dp` (14dp — the same token the filled fields inset with, so the label's first glyph sits directly above the field's first character). Purely visual; no press/state. Pair it with its field in a `Column(Arrangement.spacedBy(AMTheme.Spacing.xs.dp))`. The iOS twin is `IMFieldLabel`.

## Pickers (`controls/pickers/`)

### `AMSegmentedControl` (SegmentedControl.kt)
Generic `<Value : Any>`: `(selection, onSelectionChange, options: List<AMSegmentedControl.Option<Value>>, modifier)`. **The composable function and an `object AMSegmentedControl` share one name** — the object exists solely to host the nested `@Immutable data class Option<Value>(label: String, value: Value)` so callers write `AMSegmentedControl.Option(…)`. Values must be unique and `equals`-comparable; unknown `selection` coerces to index 0; empty `options` renders nothing.
- **Self-framed — do NOT wrap in `AMCard`:** the Android **outlined segmented-button** anatomy — a `fillMaxWidth`, 40dp-tall (`trackHeight`) group with a **transparent track**, stadium ends (`RoundedCornerShape(percent = 50)`), an **unconditional `amHairline` outline in `AMTheme.separator`** (drawn in BOTH themes, not the dark-only `amCardHairline`), and full-height 1dp `separator` dividers (`amHairlineWidth()`) between adjacent segments. Pad from screen edges at the call site. No `BoxWithConstraints`, no `amElevation`, no `snapSpringDp`.
- **Check-marked tonal selection, NO travelling thumb** — the selected segment carries a tonal grey fill (`AMTheme.neutralFill()`, cross-faded via `animateColorAsState` on `resolved(selectionColorFade)`) plus a leading 18dp (`checkIconSize`) `Icons.Default.Check` glyph beside its label. The check fades via `resolvedFinite(selectionFadeFloat)` and expands horizontally via `resolvedFiniteOrNull(selectionExpand) ?: snap()` (spatial shift → SNAPS under Reduce Motion, while the fill/fade soften). `selectionColorFade`/`selectionFadeFloat`/`selectionExpand` are Color/Float/IntSize file-level mirrors of `AMTheme.Motion.selectionFade`.
- Equal-weight text segments; label = `AMTheme.Type.label` in `AMTheme.Text.primary` for selected AND unselected (the fill + check, not a weight change, mark selection — unselected is never dimmed away).
- **a11y:** the group is `Modifier.selectableGroup()`; each segment is `Modifier.selectable(selected = isSelected, interactionSource, indication = amRipple(), role = Role.RadioButton)` — TalkBack announces each segment's selected state + position-in-group. The group's rounded `clip` trims the end segments' corners, so no per-segment clip is needed. Per-segment `MutableInteractionSource`s hoisted `remember(options.size) { List(options.size) { … } }` (house loop rule).

### `AMMenuPicker` (MenuPicker.kt)
Generic `<Value : Any>` flat row + anchored `Popup`. Slot overload `(selection, onSelectionChange, options: List<Value>, display: (Value) -> String, modifier, label)`; String overload puts `label: String` FIRST and renders it `AMTheme.Type.title` primary. Trailing cluster: `display(selection)` `AMTheme.Type.secondary` + `Icons.Default.KeyboardArrowDown` 18dp muted.
- Popup: `Popup(offset = IntOffset(0, rowHeightPx), focusable = true)`; dropdown width = trigger-row width (`onSizeChanged` px → `toDp`). **Guarded on `rowWidthPx > 0`** so it never opens before first measure. `expanded` is `rememberSaveable`.
- Dropdown surface = the AMCard recipe by hand: `Surface.primary`, `radius.lg`, `amElevation(Low)`, `amCardHairline`, vertical `spacing.xs` padding, wrapped in `Modifier.selectableGroup()`. Each item: fixed 20dp leading slot that holds `Icons.Default.Check` only when selected (slot always reserved so text aligns), label `AMTheme.Type.body` (`FontWeight.Medium` when selected, `Normal` otherwise), padding lg/md; the row is `Modifier.selectable(selected = isSelected, interactionSource, indication = amRipple(), role = Role.Button)` so TalkBack announces which option is selected (the visual check alone is invisible to TalkBack).
- **Loop keying:** each item's interaction source is `remember { MutableInteractionSource() }` wrapped in `key(option)` inside `options.forEach`, so per-row pressed state follows the row's option identity rather than its list position if `options` changes length mid-popup (the house variable-count-loop rule; SegmentedControl instead hoists a list keyed on `options.size`).

### `AMColorPicker` (ColorPicker.kt)
`(label, selection: Color, onSelectionChange, supportsOpacity = true, modifier)`. Flat row; the **whole row** is tappable (press = `amRipple()`) and opens a discrete-palette `Dialog` — Android has no system color picker, so the spec-prescribed scoped palette replaces SwiftUI `ColorPicker`; HSV wheels are out of scope. Trailing swatch: a 28dp (`ROW_SWATCH_SIZE`) `Canvas` drawing a **plain filled circle** of the `selection` color with a hairline `separator` ring (`AMTheme.hairlineWidth`, inset by half the stroke) for edge definition on light colors (no conic rainbow ring or HSV wheel — the swatch is a solid color chip). The swatch is decorative; the ROW carries a11y: `Modifier.semantics { role = Role.Button; contentDescription = "$label, <color name>" }` (name from `amColorNames`, parallel to `amColorPalette`; falls back to `label` when `selection` isn't a palette entry).
- Dialog: fixed 18-color palette (the **Material 700 row** — one 700-level tone per Material hue, in `amColorPalette` list order), 6 columns × 36dp swatches, 8dp gaps, 20dp padding, `Surface.primary` + `radius.lg` + `AMElevation.Medium`, grid wrapped in `Modifier.selectableGroup()`. Selected swatch (by `Color` equality — a selection not in the palette highlights nothing) gets a 2dp `selectionRing` border; others a hairline `separator` border. Each swatch is `Modifier.selectable(selected = isSelected, interactionSource, indication = amRipple(), role = Role.Button)` + `semantics { contentDescription = <color name> }` (from `amColorNames[i]`). Tapping a swatch fires `onSelectionChange` and closes; no Done/Cancel.
- `supportsOpacity = false` only adds an "Opacity locked" subtitle — every palette color is already fully opaque, so the flag is a visual note (iOS pass-through).
- **`AMColorSaver: Saver<Color, Long>`** is public (ULong bit pattern ↔ Long) for callers' `rememberSaveable(stateSaver = AMColorSaver)` hoisted Color state — a public addition beyond the iOS API.

### `AMDatePickerRow` (DatePicker.kt)
`(label, selection: Long /* epoch millis, UTC instant */, onSelectionChange: (Long) -> Unit, displayedComponents: AMDateComponents = Date, minimumDate: Long? = null, maximumDate: Long? = null, modifier)`. `AMDateComponents`: `Date` / `Time` / `DateAndTime`. Flat row; **only the trailing chip is tappable** (unlike ColorPicker's whole-row tap): chip = `Text.primary @ 8% alpha` fill, `Radius.sm` corners, 10×5dp padding, value `AMTheme.Type.secondary`, formatted locale-aware (`FormatStyle.MEDIUM` date, `SHORT` time, two spaces between for DateAndTime). The chip carries `Modifier.semantics { role = Role.Button; contentDescription = "$label, $formattedValue" }` so TalkBack announces it opens the picker. All java.time conversion uses `ZoneId.systemDefault()`.
- The chip opens a private house-styled `AMDatePickerDialog` (`androidx.compose.ui.window.Dialog` — no Material3): `Surface.primary`, `Radius.lg`, `AMElevation.Medium`.
  - Calendar grid (Date/DateAndTime): 7 columns **locale-first-day** — `firstDay = WeekFields.of(Locale.getDefault()).firstDayOfWeek`; every day's column = `(dayOfWeek.value - firstDay.value + 7) % 7` (also the leading-blank count for the 1st). Weekday header labels = `DayOfWeek.getDisplayName(java.time.format.TextStyle.NARROW, locale)` for `firstDay.plus(0..6)` (rotated to start at firstDay; the java enum is imported as `JavaTextStyle` to dodge the `androidx…TextStyle` clash). 36dp cells; selected day = filled circle in the accent (pure `Color.White` dark / `Color.Black` light) with the day number in `surfaceColor`; today = 4dp accent dot under the number; out-of-range days at 0.30 alpha and not clickable; leading blanks at 0 alpha. Every valid day cell is `Modifier.selectable(selected = isSelected, interactionSource = null, indication = dayCellRipple, enabled = !isDisabled, role = Role.Button)` + `semantics { contentDescription = cellDate.format(dayAccessibilityFormatter) }` — a localized `FormatStyle.LONG` date (e.g. "July 8, 2026") — so TalkBack announces each date, its selected state, and (via `selectable`'s `enabled = false`) "disabled" for out-of-range days. Month nav = `AMIconButton(Icons.AutoMirrored.Filled.KeyboardArrowLeft/Right, Small, "Previous/Next month")`, disabled (AMIconButton drops its clickable) when the adjacent month falls entirely outside `minimumDate`/`maximumDate` (inclusive bounds). One shared `MutableInteractionSource`… (the shared `dayCellRipple` = `amRipple()` with `interactionSource = null` so each tapped cell lazily makes its own).
  - Time section (Time/DateAndTime): M3 time-input style — two private `AMTimeField` numeric boxes (hour, minute) with a 24sp `:` separator between. Each field = a 64×56dp outlined box (`amHairline(amSquircle(tokens.input.radius))`, border color flips to `Text.primary` while focused) holding a centered 24sp tnum-monospaced `BasicTextField`; `KeyboardType.Number`, digit-only filter capped at 2 chars, and the value is **clamped into `0..23`/`0..59` on focus loss** (inline compare-and-set realigns the field text when the external value changes while unfocused).
  - Picked date/hour/minute are plain `remember` — **committed only on "OK"** (Date → `atStartOfDay`; Time/DateAndTime → `LocalDateTime.of(pickedDate, LocalTime.of(h, m))` with `h`/`m` re-clamped defensively), discarded on Cancel/outside-tap. Dialog actions are a right-aligned (`Arrangement.End`) `AMGhostButton("Cancel")` then `AMGhostButton("OK")` (OK rightmost). `showDialog` is `rememberSaveable` (the dialog survives rotation; its in-progress picks do not).

### `AMSlider` (Slider.kt)
NOT generic — generic type params are a Swift-ism the Android API drops. Slot overload `(value, onValueChange, valueRange: ClosedFloatingPointRange<Float>, label: String? = null, leading, trailing, modifier)` — **`leading`/`trailing` (both `@Composable () -> Unit`) are REQUIRED (no default), pass `{}` for none**; that non-default keeps the slot overload distinct from the convenience overload so a bare `AMSlider(value, onValueChange, valueRange)` resolves unambiguously to the convenience one. Convenience overload takes one **sealed `AMSliderDecoration?` per side** — `leading`/`trailing`, default `null` — where `AMSliderDecoration` is `Icon(ImageVector)` | `Text(String)` (the iOS twin uses the same enum shape; "icon AND text on one side" is unrepresentable — no runtime precedence). Rendered by private `AMSliderDecorationLabel`: `Icon` = 20dp `Icon.muted`; `Text` = `AMTheme.Type.caption` `Text.secondary` with **tabular digits (`fontFeatureSettings = "tnum"`), NOT `FontFamily.Monospace`** (iOS `.caption.monospacedDigit()` — digits column-align while non-digits like the "m:ss" colon keep their proportional width; a full monospace font would pad the colon into its own wide cell, reading "0 : 00"). Optional `label` renders `AMTheme.Type.body` above the track. Visual-only: no internal value state.
- **Material 3 slider anatomy** (custom `Canvas` + `pointerInput`, no Material3). A thick **16dp** (`trackHeight`, `trackRadius` 8dp) fully-rounded track SPLIT into two capsule segments with a 6dp (`trackGap`) notch on each side of the handle: active (`0 →` handle notch) = the live **`tokens.semantic.accent.resolve(isDark)`** (flows with the demo accent toggle), inactive (notch `→` trailing edge) = the neutral control-fill grey (Black/White @ 8%, the `neutralFill` recipe). A narrow **vertical accent handle** — 4dp × 44dp (`handleWidth`/`handleHeight`, `handleRadius` 2dp), drawn by the internal `drawSliderHandle` — sits in the notch, **no shadow and no white pill** (it carries the accent tint like the active fill). A 4dp **stop-indicator dot** (`stopDotRadius` 2dp) marks the trailing cap: accent-colored on the inactive grey, flipping to `AMTheme.Surface.primary` (the on-accent contrast tone) once the value hits the extreme and the handle passes it. Canvas/touch height = 44dp (`sliderHeight`); the handle centre travels `handleHalf … width − handleHalf`, so the usable span (`usableWidth = width − handleWidth`) excludes the handle's own footprint.
- **a11y:** the track `Modifier.semantics(mergeDescendants = true)` sets `progressBarRangeInfo = ProgressBarRangeInfo(value, valueRange)` + a `setProgress { onValueChange(it.coerceIn(...)); true }` action + `contentDescription = label` (when non-null) — TalkBack reads the value and can adjust it, the accessibility SwiftUI's native Slider gives for free.
- **Positioning is ABSOLUTE — tap jumps, drag chases the finger.** Two `pointerInput(rangeStart, rangeEnd)` blocks: `detectTapGestures` and `detectHorizontalDragGestures` both map position→value via `amSliderPositionToValue(pos.x, trackWidthPx, valueRange)` on every event (drag consumes the change). NO delta-accumulator and NO `value` mirror — the Canvas node never moves, so node-local position math is stable (contrast the FAB, which must use relative `positionChange`). `trackWidthPx` (usable width = `width − handleWidth`) is written in the draw pass and read in the gesture coroutines — the draw→gesture bridge. Both blocks invoke `onValueChange` through a `rememberUpdatedState` holder (`currentOnValueChange`) so the `(rangeStart, rangeEnd)`-keyed loops never fire a stale callback when the caller passes a new lambda without changing the range.
- Pure math lives as internal top-level functions, JVM-tested without Compose: `amSliderValueToFraction` (clamps to [0,1]; degenerate `end <= start` → 0) drives the draw-pass fraction; `amSliderPositionToValue` (clamps `pos/width` to [0,1]; `trackWidthPx <= 0` → `valueRange.start`) drives both gestures; plus `amSliderFractionToValue`, `amSliderClampValue`, `amSliderDragDeltaToValueDelta` (returns 0 when `trackWidthPx <= 0`).

### `AMStepper` (Stepper.kt)
`Int` values only — fractional values use `AMSlider`. Slot overload `(value, onValueChange, valueRange: IntRange, step = 1, modifier, label /* leading-label slot */)`; String overload `(value, onValueChange, valueRange, step, label: String, modifier)` renders the `AMTheme.Type.title` headline. Callbacks fire `(value ± step).coerceIn(valueRange)`; the minus button disables at `value == valueRange.first`, the plus at `== last`.
- The ± affordances are **two SEPARATE square tonal buttons** (`AMStepperButton`, ~40dp square `stepperButtonSize`, file-level private geometry vals — no shared metrics object), each clipped to `RoundedCornerShape(tokens.radius.sm)` and filled with `AMTheme.neutralFill()` — squared-off tonal icon buttons with a **dark-mode-only `amCardHairline`** edge, **no joined capsule and no interior divider**. The ± glyphs render at 18dp (`stepperGlyphSize`); the live value readout sits **between** the minus and plus buttons, with `spacing.sm` gaps. Press = `amRipple()` bounded to each clipped button.
- **Press-and-hold auto-repeat** (mirrors `UIStepper`): `AMStepperButton` replaces `clickable` with a `pointerInput(enabled)` hold loop — fire once immediately, then `withTimeoutOrNull(interval) { waitForUpOrCancellation(); true }` interleaves the accelerating timer with up/cancel detection in ONE coroutine (no leaked repeat job). Timing: `STEPPER_INITIAL_DELAY_MS` 500 → `STEPPER_REPEAT_INTERVAL_MS` 100, accelerating to `STEPPER_FAST_INTERVAL_MS` 50 after `STEPPER_ACCELERATE_AFTER_MS` 2000 held. `rememberUpdatedState(onClick)` keeps the loop targeting the latest `value`; the ripple is manual (`Modifier.indication(interactionSource, amRipple())` + emitted `PressInteraction.Press`/`Release`). Keyed on `enabled` so reaching a bound cancels the hold.
- **a11y:** each button `semantics { role = Role.Button; contentDescription = "Decrease"/"Increase"; if (enabled) onClick { onClick(); true } else disabled() }` — an accessibility click fires a single step; disabled buttons announce "disabled".
- **Disabled button stays at full alpha with the glyph tinted `Icon.disabled`** — a state tint, deliberately distinct from the press feedback (`amRipple()` sweep) — and drops its gesture.
- **The minus glyph is a Canvas-drawn 12×2dp rounded bar** — `Icons.Default.Remove` lives in extended icons, which `:mtrls` excludes; plus is `Icons.Default.Add` (core). `AMStepperButton(icon = null)` selects the bar.
- Readout: `AMTheme.Type.body` (16sp) `.copy(FontFamily.Monospace, fontFeatureSettings = "tnum")`, centered in a `widthIn(min = 40.dp)` (`stepperReadoutMinWidth`) cell — so the row doesn't shift as digit count changes.

### `AMToggleRow` (Toggle.kt)
`(checked, onCheckedChange, modifier, label: ColumnScope slot)` + String overload `(label, checked, onCheckedChange, modifier)` (`AMTheme.Type.title`). The label slot is `ColumnScope` so multi-line title+subtitle stacks naturally. **The whole row is the tap target**: `Modifier.toggleable(value, interactionSource, indication = amRipple(), role = Role.Switch, onValueChange)`; press = the `amRipple()` sweep (rect-bounded over the row). No `enabled` param.
- Trailing switch is fully Canvas-drawn (`drawBehind`) in **M3 switch morphology** — no drop shadow. Track = 52×32dp capsule; off fill = the `neutralFill` recipe (Black/White @ 0.08, computed straight from `isDark` in the draw scope) + a 1dp `AMTheme.separator` border; **on fill = the live, overridable `tokens.semantic.accent`** (the primary tint — follows the app/subtree accent decision, NOT a fixed hue, NOT success green), border animating to transparent. Thumb: off = 16dp `AMTheme.Icon.muted`; **on = 24dp `AMTheme.Surface.primary` resolved** (white light / black dark, so the knob adapts like every other mtrls surface — not pure white); pressed (either state) = 28dp. When ON, a 16dp (`thumbIconSize`) `Icons.Default.Check` glyph tinted the accent fades in on the thumb; OFF shows none. Both rest **centres** sit 16dp in from their respective track ends (off thumb edge 8dp from the near end, on thumb edge 4dp from the far end).
- **Two motion curves.** Thumb position (0→1 fraction), diameter, AND the ON check-glyph alpha animate on the file-level `thumbSnapSpring = spring<Float>(0.86, 384)` — the lockstep mirror of `AMTheme.Motion.snapSpring` — routed through `tokens.motion.resolved` (softens, never snaps). Track fill, border, and thumb colours cross-fade on `selectionColorFade = tween<Color>(150, EaseInOut)` — the Color-typed lockstep mirror of `AMTheme.Motion.selectionFade` (`animateColorAsState` needs `AnimationSpec<Color>`, so the Float token can't be passed directly).
- **`pressed` is read via `collectIsPressedAsState()` off the row's `MutableInteractionSource`** — a deliberate, documented **non-press-feedback** use: it drives the thumb GEOMETRY (swell to 28dp), never an alpha dim. Press feedback itself stays the `amRipple()` sweep, so this read does not violate the no-opacity-dim rule.
