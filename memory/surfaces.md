# Surfaces

Static frames a screen is built from (`surfaces/frames/`) versus transient layers presented by state (`surfaces/overlays/`), plus the internal blur and dismissal primitives every overlay shares.

## The frames vs overlays split

- **`frames/`** — "I sit here." Always-present chrome composed inline: `Card.kt`, `Toolbar.kt`, `Panel.kt`, `Section.kt`, `Disclosure.kt`.
- **`overlays/`** — "I appear when state says so." Host composables driven by `isPresented: Boolean` or `item: T?`: `Toast.kt`, `Sheet.kt`, `Banner.kt`, `Alert.kt`, `LoadingOverlay.kt`, `ActionsOverlay.kt`, `FloatingActions.kt` (the scene FAB hub), plus the mostly-internal blur/dismissal primitives `BackdropBlur.kt` (carries the public `AMBackdropBlur`) and `Dismissal.kt`, and the public decorative `PausedBackdrop.kt`.

No unit tests exist for surfaces — everything here is visual; verification is via the `@Preview`s in each file and the demo app (test policy in `build.md`).

## The two hairline modifiers (taxonomy that matters)

- `amCardHairline(shape)` — **dark-mode-only** `selectionRing` ring. Used by `AMCard` and `AMToolbarButton`. (`AMPanel`'s back arrow is a borderless `AMIconButton`, not a chip — no hairline.)
- `amHairline(shape)` — **unconditional** ring, both modes. Used by the Toast pill, Banner card, Sheet card, and Alert card (floating overlay surfaces always show the ring so they read over any substrate). `AMAlertCard` adds `amHairline` *on top of* `AMCard` precisely because the card's built-in hairline is dark-only.

Chrome layering is always **elevation → background fill → hairline** in the modifier chain: `amElevation` draws behind the fill (`drawBehind`), so the shadow bleeds onto the page substrate; the hairline draws inside bounds on top of the fill.

## AMCard — base surface + demotion contract (`frames/Card.kt`)

`AMCard(modifier, padding: PaddingValues? = null, radius: Dp? = null, elevation: AMElevation = Low, content)`. A `@Composable` function, **not** a Modifier extension, because it must call `CompositionLocalProvider` (the composable-vs-Modifier rule in `conventions.md`).

Reads `LocalAMSurfaceStyle`:
- **Elevated** (screen-root default): `Surface.primary` fill shaped by `amSquircle(radius ?: tokens.radius.lg)` (16dp, continuous/squircle corners — the signature look, never a plain `RoundedCornerShape`), `amElevation(elevation)`, dark-only `amCardHairline`, a final `clip(shape)`, and `padding` applied when non-null. Chain order is `amElevation → background → amCardHairline → clip`: **clip is last so it bounds only the content slot** — full-bleed children (AMDisclosure's rect-bounded ripple, AMToggleRow/AMListRow fills) are clipped to the squircle instead of painting square corners over it, while the shadow and hairline drawn earlier in the chain stay unclipped (the shadow still bleeds onto the page).
- **Flat** (inherited inside another card): renders **nothing** — no fill/clip/shadow/hairline, and `padding` is **skipped** entirely. The passed `modifier` still applies (layout constraints survive).

The card **always provides `AMSurfaceStyle.Flat` into `LocalAMSurfaceStyle` for its content slot**, regardless of its own style — that is the nesting contract preventing double-padding and shadow-on-shadow. `AMSection`, `AMDisclosure`, `AMBanner`'s card, and `AMAlert`'s card all build on `AMCard`. Widgets (pickers, toggles, inputs) do not read the local; demotion applies only to card surfaces.

`padding = null` means "caller manages insets" — `AMBanner` passes null and pads its own Row.

## AMToolbar + AMToolbarButton + AMButtonRole (`frames/Toolbar.kt`)

**`AMButtonRole`** — `@Immutable enum`, single case `Destructive`. **Declared in this file and reused library-wide** (`AMAlertAction`, `AMActionGridButton`, button String-overloads). Never redeclare it; import from `surfaces.frames`.

**`AMToolbarChipMetrics`** (internal object): chip `size = 36.dp`, `iconSize = 18.dp`. Backs `AMToolbarButton`'s `Regular` size. (`AMPanel`'s bar is built from `AMIconButton`, so it does not use this metric.)

**`AMToolbarButtonSize`** — `@Immutable` enum, `Regular` (36dp circle / 18dp glyph, backed by `AMToolbarChipMetrics`) and `Prominent` (60dp circle / 30dp glyph — a hero action such as a media play/pause). Both share the identical `Surface.primary` fill + dark-only hairline + `amElevation(Low)` recipe; only the internal `diameter`/`iconSize` props change.

**`AMToolbar(modifier, title: String? = null, leading/trailing/center: (@Composable () -> Unit)? = null)`** — top action strip, **no fill, no hairline**, floats on the page substrate. Layout trick: the center content is absolutely positioned via `Box(Alignment.Center)`, and the edge `Row` (`SpaceBetween`) is overlaid in the same Box — title stays optically centered regardless of edge-cluster widths. Between the two edge slots sits an invisible **minimum-gap `Spacer(widthIn(min = tokens.spacing.md))`** — the twin of iOS `Spacer(minLength: tokens.spacing.md)`; with `SpaceBetween` it guarantees ≥ md between the leading and trailing clusters even when they are wide enough to otherwise abut, and floats unseen mid-row in the common case. When exactly one of leading/trailing is absent, a **36dp balancing `Spacer`** is inserted on that side; when both are absent, 0dp spacers. `center` non-null overrides `title`; `title` renders `AMTheme.Type.title` `Text.primary`. Padding is `tokens.titleBarInsets` (14dp horizontal / 10dp vertical). (`AMToolbar` stays the chrome-less floating strip — used by the demo's Auth/Gallery-select action bars — whereas both `AMPanel` and the demo's `ScenePanelChrome` build their own native Android app bar from `AMIconButton` + `AMDivider`. `AMPanel` and `ScenePanelChrome` deliberately share **identical** bar anatomy so scene panels read identically to the library primitive — each builds its own copy of the 64dp back-arrow / left-title / optional-trailing bar; there is no shared composable between the library and the demo.) **Visual only** — slot taps belong to caller content.

**`AMToolbarButton(icon, modifier, size: AMToolbarButtonSize = Regular, role: AMButtonRole? = null, enabled: Boolean = true, contentDescription: String, onClick)`** — the round surface chip: a `size.diameter` circle, `Surface.primary` fill, `amElevation(Low, CircleShape)`, dark-only `amCardHairline`, `size.iconSize` glyph via `foundation.Image` + `ColorFilter.tint`. Glyph-tint precedence: `!enabled` greys to `Icon.disabled` (via `.resolve(isDark)`), then `role == Destructive` tints `AMTheme.destructive`, otherwise `Text.primary`. `enabled` is passed straight through to `clickable(enabled = ...)`, so a disabled chip drops the click and its ripple while the surface chrome (fill/hairline/shadow) stays **full-alpha** — only the glyph dims. Press feedback: `amRipple()` bounded to the clipped circle (the chip is `clip(CircleShape)`'d), wired as `indication = amRipple()` with a hoisted `MutableInteractionSource`. **`contentDescription` is required and non-nullable** (set via `semantics {}` on the outer Box, which also sets `role = Role.Button` so TalkBack announces the chip as a button; the inner Image gets `contentDescription = null`). For icon buttons *inside* a card's action row use `AMCardButton` instead — it is deliberately flat since the surrounding card supplies fill + shadow.

## AMPanel + AMPanelHost (`frames/Panel.kt`)

**`AMPanel(title, onBack, modifier, trailing = null, content)`** — slide-in detail frame chrome with an **Android-native top app bar** (deliberate re-Androidification: where iOS `IMPanel` floats a *centered* title over a circular back chip with no bar chrome, `AMPanel` keeps the mtrls signature — type ramp, hairline, motion — but adopts native top-app-bar anatomy so it reads as an Android screen). The bar is a `fillMaxWidth` Row carrying `statusBarsPadding()` **then** `height(64.dp)` (clears the status bar / cutout, then fixes the bar to the Material small-app-bar class), padded `horizontal = spacing.xs` (4dp gutter). Contents start→end: a **borderless back arrow** — `AMIconButton(icon = Icons.AutoMirrored.Filled.ArrowBack, size = Medium /*44dp tap, 22dp glyph*/, contentDescription = "Back", onClick = onBack)` (no surface chip — the Android navigation-icon idiom; bounded `amRipple` disc + `Role.Button`) → `Spacer(width spacing.xs)` → the **left-aligned title** (`AMTheme.Type.title` `Text.primary`, `Modifier.weight(1f)`, `maxLines = 1` / `TextOverflow.Ellipsis`) → when `trailing != null`, a `Spacer(width spacing.sm)` then the caller-sized `trailing()`. **No optical-centering trick and no balancing spacer** — the title is left-aligned (weight claims the slack), so nothing needs centering. Directly under the bar sits a full-bleed **`AMDivider()`** (the mtrls hairline, `AMTheme.separator`) — the always-on "attached app bar" cue that replaces iOS's chrome-less floating title (the library carries no scroll-aware/collapsing bar machinery to gate it on). The `statusBarsPadding()`/`height` live on the bar Row only, so the body sits flush under the divider with no double top inset. `AMPanel` itself installs **no** back gesture — tapping the arrow is the only dismissal a standalone `AMPanel` offers; the system predictive-back gesture lives on `AMPanelHost`. **`content` is bounded to the remaining height** below the bar+divider: the body Column wraps `content()` in `Box(fillMaxWidth().weight(1f))` so it fills the space like a Scaffold body and a scrollable body (`verticalScroll`/`LazyColumn`) measures against a **finite** height. Without the weight the body Column would hand its non-weighted `content()` child an infinite main-axis max and crash any scroll container (`IllegalStateException: … infinity maximum height`).

**Predictive back (`AMPanelHost` only):** `androidx.activity.compose.PredictiveBackHandler(enabled = isPresented)` tracks the Android system back gesture — called **unconditionally** (never inside an `if`), the `enabled` flag toggles it. The block collects `event.progress` into a `var backProgress by mutableFloatStateOf(0f)`; the panel layer reads it via `graphicsLayer { translationX = size.width * 0.3f * backProgress; alpha = 1f - 0.1f * backProgress }` (a peek toward the trailing edge, no-op at rest). On normal completion it sets `backProgress = 0f` then calls `onDismiss()` (so the 250ms slide-out owns the exit). **Gotcha:** the handler's `onBackCancelled` cancels the gesture coroutine's own job, so the cancel snap-back **must** launch on a separate `rememberCoroutineScope()` — inside the `catch (CancellationException)` an `Animatable(backProgress)` animates to 0f on `settleSpec` (the file-private `snapSpringFloat` 0.86/384 — mirror of `AMTheme.Motion.snapSpring` — resolved through the RM policy, so it softens under Reduce Motion) via `backScope.launch`, then **re-throws** the exception per the API contract. There is no leading-edge drag strip — the system owns the back affordance.

**`AMPanel` carries no background.** `AMPanelHost` applies `Surface.page` behind it; direct `AMPanel` callers supply their own substrate.

**`AMPanelHost(isPresented, title, onDismiss, trailing = null, panelContent, hostContent)`** — the presenter; **has no `modifier` parameter**. Wraps `hostContent` in a `fillMaxSize` Box and animates the panel via `AnimatedVisibility`: `slideInHorizontally`/`out` from the trailing edge (`initialOffsetX = fullWidth`) + fade, all on `tween(250)` (`panelPresentationDurationMs` — longer than the 180ms `overlayFade` because the panel travels the full screen width). The panel inside is `fillMaxSize().graphicsLayer{ …predictive-back peek… }.background(Surface.page)`. **Full-coverage host — attach at the scene root, never inside a scrollable column.** The `fillMaxSize` panel needs a bounded height; attaching the host inside a `verticalScroll` column (unbounded height) feeds the panel infinite height and crashes on present. In the demo this means the Panel entry sets `ownsScaffold = true` and wraps `ComponentPage` (same pattern as `AMActionsOverlay`; see `demo.md`).

## AMSection (`frames/Section.kt`)

`AMSection(title, modifier, footer: String? = null, style: AMSectionStyle = Card, inset: Boolean = true, content)`. Reads spacing/insets from `LocalAMTokens` (like `AMCard` reads `tokens.radius`) so an `AMTokensProvider` transform re-tunes the rhythm; values equal `AMTheme.Spacing.*` at defaults. Column with `tokens.spacing.md` (12dp) vertical gaps: `AMSectionHeader(title)` (lives in `content/`, has no modifier param — the horizontal inset is applied by a wrapping Box) → content block → optional footer (`AMTheme.Type.caption`, `Text.secondary`). Both style branches wrap the content slot in `Box(fillMaxWidth(), CenterStart)` so it stretches full-width leading-aligned, mirroring iOS `.frame(maxWidth: .infinity, alignment: .leading)`.

`AMSectionStyle` (`@Immutable` enum):
- **Card** (default): content in `AMCard(padding = tokens.blockInsets)` (16dp all sides), card inset `tokens.spacing.lg` (16dp) horizontally when `inset = true`.
- **Flat**: full-bleed `Surface.primary` Column padded `tokens.spacing.lg` all sides, no corners, no elevation. **The flat fill always extends to the screen edges regardless of `inset`** — `inset` only affects header/footer (and the Card-style card).

`inset = false` strips horizontal padding from header/footer/card for full-bleed hosts.

## AMDisclosure (`frames/Disclosure.kt`)

Four overloads: {composable `label` slot | `String` label} × {hoisted `expanded`/`onExpandedChange` | self-managed `initiallyExpanded = false`}. Self-managed uses `rememberSaveable`. The String overloads render the label with `AMTheme.Type.title` `Text.primary` (private `AMDisclosureLabel`).

Built on `AMCard` (so it participates in the demotion contract). Reads its spacing from `LocalAMTokens` (`tokens.spacing.lg`/`tokens.spacing.md`) so an `AMTokensProvider` transform re-tunes it; `AMTheme.rowMinHeight` stays a theme constant (deliberately not tokenized). Header row: `heightIn(min = AMTheme.rowMinHeight.dp)` (64dp), `toggleable(role = Role.Button, indication = amRipple())` with a hoisted `MutableInteractionSource`, plus `semantics { stateDescription = "Expanded"/"Collapsed" }` (a disclosure is an expander, **not** a boolean switch — mirrors the iOS Button trait). Press = the `amRipple()` sweep rect-bounded inside the clipped `AMCard`, padding `tokens.spacing.lg` horizontal / `tokens.spacing.md` vertical. Label fills remaining width; trailing chevron is `Icons.Default.KeyboardArrowDown` 20dp tinted `Icon.muted`, rotated **0° expanded / −90° collapsed** via `graphicsLayer { rotationZ }`.

Animations — two file-private springs that **must stay value-identical** (lockstep comment in the file): `disclosureToggleSpring = spring<Float>(0.86, 321)` drives chevron rotation + content fade; `disclosureSlideSpring = spring<IntOffset>(0.86, 321)` drives `slideInVertically`/`slideOutVertically` (`initialOffsetY`/`targetOffsetY = { -it }`, i.e. from/towards the top edge) — the content block **translates** in from the top behind the header, matching iOS `.opacity.combined(with: .move(edge: .top))`, not a clip-grow reveal. Diverging the two springs visibly splits the slide from the opacity fade. (321/0.86 sits between `snapSpring` 384 and `presentSpring`'s 0.85 damping — a bespoke value, not a token.)

Expanded content sits below an `AMDivider()` inside the same card, padded `tokens.spacing.lg` horizontal / `tokens.spacing.md` vertical, items spaced `tokens.spacing.md`.

## Overlay host pattern (all of `overlays/`)

Every overlay is a **host composable that wraps the scene content as the trailing `hostContent` lambda**. There are no sibling `Modifier.amX()` overlay presenters — the host-wraps-content shape is the only pattern, so never add one. Hosts nest for stacking; the inner host's overlay draws under the outer host's overlay. Every host KDoc says **attach at the scene root** — wrapping a sub-composable clips the overlay/tap-catcher/blur to that node's bounds.

**Every host reports the overlay-active signal down** (see `AMFloatingActionsHost + LocalAMOverlayActive` below). All seven hosts — `AMToast`, `AMBanner`, `AMAlert`, `AMSheet`, `AMLoadingOverlay`, `AMActionsOverlay`, and frame-side `AMPanelHost` — wrap their `hostContent()` in `CompositionLocalProvider(LocalAMOverlayActive provides (<own presented> || inherited))`. The **inherited value is read at the host's own composable scope, BEFORE the provider** (`val inheritedOverlayActive = LocalAMOverlayActive.current`), so nested hosts OR correctly: each provides `own || inherited`. Own-presented flag is the host's existing state — `item != null` (Toast/Banner/Alert) or `isPresented` (Sheet/LoadingOverlay/ActionsOverlay/PanelHost). The provider wraps the innermost `hostContent()` call (inside the blur Box for blurring hosts). `LocalAMOverlayActive` lives in `overlays/FloatingActions.kt`, same package as the six overlay hosts (no import); `AMPanelHost` (in `frames/`) imports it.

Two presentation ergonomics:
- **`item: T?`** — `AMToast(item, onDismiss, …)`, `AMBanner(item, …)`, `AMAlert(item, …)`. Non-null presents; `onDismiss` fires and the **caller** must null the item. Items are `@Immutable data class`es with `id: UUID = UUID.randomUUID()` — animations and auto-dismiss timers key on `item?.id`, so swapping to a new instance (fresh UUID) without a null transition restarts the timer; reusing an id does not.
- **`isPresented: Boolean`** — `AMSheet`, `AMLoadingOverlay`, `AMActionsOverlay` (and frame-side `AMPanelHost`).

**Exit-retention pattern** (Toast, Banner, Alert): the last non-null item is kept in a `remember { mutableStateOf(item) }` updated only when `item != null`, so the surface has content to render while `AnimatedVisibility` plays the exit. Alert additionally wraps the card in `AnimatedContent(targetState = renderItem, contentKey = { it.id })` so an A→B item swap (no null between) **replays the scale/fade pop** — the outer `AnimatedVisibility` owns null↔non-null, the inner `AnimatedContent` owns A→B, mirroring iOS's `.id(item.id)` re-fire.

**Typed spring mirrors:** the motion tokens are `AnimationSpec<Float>`; slide transitions need `FiniteAnimationSpec<IntOffset>`, `animateDpAsState` needs `AnimationSpec<Dp>`, and `fadeIn`/`fadeOut` need `FiniteAnimationSpec<Float>` (the token's wider static type won't satisfy them). Each file declares its own `private val` mirror with a lockstep comment naming the token — these are **duplicated per file by design**: `presentSpringIntOffset` (0.85/321 + `IntOffset.VisibilityThreshold`) AND `presentSpringFloat` (0.85/321) in Toast.kt AND Banner.kt; `modalSpringIntOffset` AND `modalSpringFloat` (both 0.86/224) in Sheet.kt (ActionsOverlay.kt carries neither — it fades as one opacity group with no slide); `overlayFadeDp` (`tween<Dp>(180, EaseInOut)`) in LoadingOverlay.kt and ActionsOverlay.kt; `snapSpringDp` (0.86/384) in Alert.kt; `snapSpringFloat` (0.86/384) in Dismissal.kt and Alert.kt. The `*Float` mirrors exist because each transient overlay drives its **fade on its own present/modal spring** (not the 180ms overlayFade tween) so opacity tracks the slide/scale as one motion. If a token in `Theme.kt` changes, all mirrors must be updated by hand.

## Dismissal primitives (`overlays/Dismissal.kt`) — all internal

**`Modifier.amTapCatcher(action)`** — `fillMaxSize()` + `pointerInput { detectTapGestures }`. Invisible full-bounds tap target. Used by `AMSheet` and `AMActionsOverlay`.

**`AMDragDismissDirection`** — `Up` (Banner) / `Down` (Toast, Sheet). (`AMActionsOverlay` does **not** use `amDragDismiss` — its drag-to-dismiss lives on the full-screen catcher and is end-evaluated; see its section.)

**`Modifier.amDragDismiss(direction, threshold: Dp, dragOffset: MutableState<Float>, onDismiss, minActivationDistance: Dp = 0.dp)`** — `composed {}` with `rememberCoroutineScope`; `detectVerticalDragGestures` inside `pointerInput(direction, threshold, onDismiss, minActivationDistance)`. Semantics:
- **Caller owns `dragOffset`** (the gesture-coupled hot-state exception to the plain-var rule) and applies it as `Modifier.offset { IntOffset(0, dragOffset.value.roundToInt()) }` for live tracking (Sheet clamps with `.coerceAtLeast(0)`). Hosts key the `remember` on `item?.id` (Toast/Banner) or `isPresented` (Sheet) so it resets to 0f per presentation.
- **Net-translation tracking:** a plain `var translation` accumulates every signed delta since the gesture start (the Compose twin of `value.translation.height`); each move writes `dragOffset.value = translation` **clamped to the dismiss direction** (`coerceAtLeast(0f)` for Down, `coerceAtMost(0f)` for Up). The surface follows the finger **both ways** — reversing the drag returns the offset toward 0, clamping at rest once the net crosses back past the start. This is NOT a positive-only ratchet: a drag to +70 then back to net +40 rests at 40 and does not dismiss.
- **Activation gate:** total `abs` travel (a plain `var` inside the pointerInput block) must exceed `minActivationDistance` before a delta is written to `dragOffset` (`translation` still accumulates from the first delta). The param exists (default 0dp) but **no overlay passes a non-zero value** — the drag surfaces all make the affordance explicit (Sheet drag handle, Toast/Banner whole-surface).
- **On drag end:** the commit test reads the **net `translation`** against `threshold` in the gated direction (not the offset, not raw travel). On a **committed** dismiss it calls `onDismiss()` then resets `dragOffset.value = 0f` **without animation**, so only the surface's exit transition plays (an animated snap-back would fight the removal transition — two curves, opposite directions, one view). On a **rejected** drag or **cancel** it springs `dragOffset` back to 0f with `snapSpringFloat` (0.86/384) via an `Animatable` seeded from the current value, writing each frame back into `dragOffset.value` inside `scope.launch`.

Thresholds — every consumer reads the overridable `tokens.motion.*` (so an `AMTokensProvider` transform re-tunes them), defaulting to the `AMTheme.Motion` constants (dp): `dismissThreshold = 60` — Sheet (`amDragDismiss`) and ActionsOverlay (catcher drag). `dismissThresholdCompact = 30` — Banner (up), Toast (down).

## Backdrop blur + scrim (`overlays/BackdropBlur.kt`) — one public, two internal

**`AMBackdropBlur(radius: Dp = AMTheme.Overlay.blurRadius.dp, modifier, content)`** — the **public**, self-contained tint-free Gaussian blur; the Compose mirror of iOS `IMBackdropBlur`. A `@Composable` that wraps `content` in a `Box(modifier.amBackdropBlur(radius))` so the wrapped substrate renders blurred. Tint-free is the contract — **no scrim in either light or dark mode** (for blur+scrim reach for `amPausedBackdrop`/`AMPausedSubstrate`; for a blocking dismissable layer, `AMActionsOverlay`). **Divergence from iOS (platform-mandated):** iOS `IMBackdropBlur` is an overlay View that samples the *sibling* substrate *behind* it; pure Compose cannot sample behind a sibling, so `AMBackdropBlur` blurs the content it **wraps** (same reason every blurring host wraps `hostContent`). `radius` ≤ 0 renders content crisp; blur is a **no-op in `@Preview`** (RenderEffect), validate on device/emulator (API 31+). Callers clip the `modifier` to a shape to contain the edge bleed (the demo clips to a squircle, iOS clips to a rounded rect). Demo: `demo/.../pages/content/BackdropBlurPage.kt` (`backdropBlurEntry`, id `content-backdrop-blur`) — a crisp `AMRemoteImage`, then the same image wrapped in `AMBackdropBlur`.

**`Modifier.amBackdropBlur(radius: Dp)`** (internal) — `graphicsLayer { renderEffect = BlurEffect(px, px, TileMode.Clamp) }`. The shared blur mechanism behind public `AMBackdropBlur`, `amPausedBackdrop`, and every blurring overlay host. Pure Compose cannot sample behind a sibling, so blurring hosts apply this modifier **to the wrapped `hostContent` layer**, never to a sibling overlay node (no `haze` dependency). The radius parameter is a plain `Dp` — hosts pass an `animateDpAsState` value (0dp ↔ `AMTheme.Overlay.blurRadius` = 20, on `overlayFadeDp`) and the graphicsLayer lambda re-executes per frame. **Guard: radius ≤ 0 sets no renderEffect** — `BlurEffect` crashes on non-positive radii. **Deliberately unclipped: the layer keeps `clip = false`**, so the blur paints past the host bounds (Skia expands output ~3σ ≈ 1.7 × radius) and chrome adjacent to a sub-region host — e.g. an app top bar above the wrapped content — washes under the blur while the overlay is up. Never set `clip = true` here. Caveats by design: the washed-over chrome stays tappable, and the host's scrim/tap-catcher do not extend over it. minSdk 31 guarantees RenderEffect; no version guard. **Gotcha: Android Studio's preview renderer does not execute RenderEffect — blur is a no-op in `@Preview`;** validate on emulator/device (the Alert previews sidestep this by rendering `AMAlertCard` directly).

**`AMDarkScrim(modifier, opacity = AMTheme.Overlay.scrimOpacity /* 0.4 */)`** — full-screen `Color.Black.copy(alpha)` rendered **only in dark mode**; in light mode it composes nothing. Reads **`LocalAMIsDarkTheme`, never `isSystemInDarkTheme()`** (so the demo's manual theme toggle is honored). Carries no gesture modifier — pointer events pass through; hosts layer their own tap-catcher/input-blocker on top. Rationale: the pure blur in dark mode shows `Surface.page` (12,12,13) verbatim, which isn't "paused" enough; black at 0.4 pulls brightness below the substrate without adding a tint. Used by Alert, LoadingOverlay, ActionsOverlay.

## AMPausedBackdrop + AMPausedSubstrate (`overlays/PausedBackdrop.kt`) — public, decorative

The "paused world" treatment: blur + scrim *behind* foreground content so a substrate reads as stilled. **Public and purely decorative** — full-bleed and non-interactive, with **no** tap-catcher, input blocker, `isPresented` gate, or modality. Distinct from the modal overlay hosts (Alert / LoadingOverlay / ActionsOverlay), which own dismissal. The iOS twins are `imPausedBackdrop` / `IMPausedScrim`.

**`AMPausedScrim`** (`@Immutable` enum): **Modal** = the `AMDarkScrim` recipe (dark-mode-only black at `Overlay.scrimOpacity` 0.4; light mode is blur alone); **Page** = a translucent `Surface.page` wash at **0.55** (`PAUSED_PAGE_WASH_OPACITY`, a **private const, deliberately NOT a token** so a theme override can't distort the photo-detail wash). Private `pausedScrimColor(scrim, isDark)` resolves the flat color (Modal → `Color.Transparent` in light) and is shared by both forms.

**`Modifier.amPausedBackdrop(scrim = Modal, blurRadius = Overlay.blurRadius.dp)`** — static form, a `composed {}` (reads `LocalAMIsDarkTheme`). Blurs the node's **content** (its children, or drawing chained *after* the modifier) via internal `amBackdropBlur`, then draws the scrim crisply on top. Adds **no pointer input**. **Chain order is load-bearing:** `drawWithContent { drawContent(); drawRect(scrimColor) }` sits **outside** `amBackdropBlur`'s `graphicsLayer`, so the scrim paints over the already-blurred substrate instead of being swept into the blur. Usage: `Box(Modifier.amPausedBackdrop(Page)) { PhotoView() }` blurs the child; anything chained after the modifier (`.amPausedBackdrop(...).background(brush)`) also lands inside the blur layer (the same reason overlay hosts wrap `hostContent` — Compose can't blur a sibling).

**`AMPausedSubstrate<T>(key, scrim = Modal, blurRadius = …, modifier = Modifier, content: @Composable (T) -> Unit)`** — crossfading form for photo-detail substrates. `content` cross-dissolves on `key` via **`AMCrossfade`** (house 250ms EaseInOut, instant under `LocalAMReduceMotion`; timing is fixed, not theme-overridable — the iOS twin is the private `pausedSubstrateCrossfade`) **inside a fixed inner `Box` that carries `amBackdropBlur`**. That blur Box is never keyed on `key`, so its `graphicsLayer` keeps stable identity and re-samples the cross-dissolving content live — the blur does **not** re-ramp or flash on swap (the Android translation of iOS's "stable blur above a re-identifying substrate": here the blur must wrap the layer it decorates, it can't sample a sibling). The scrim (`PausedScrimLayer`, private) is a stable sibling **above** the blur — Modal reuses `AMDarkScrim()`, Page is a `Surface.page`-wash `Box`. Both fill the node; pass a **bounded, scene-filling `modifier`** (e.g. `fillMaxSize()`) or the backdrop collapses.

Blur is a **no-op in `@Preview`** (RenderEffect); the scrim still draws — validate blur on device/emulator (API 31+). Demo: `demo/.../scenes/gallery/GalleryDetail.kt` (`DetailBackdrop`) drives an `AMPausedSubstrate` keyed on the current photo id with `AMPausedScrim.Page` — the full-bleed page wash blurs and cross-dissolves the gallery-detail backdrop as you swipe between photos.

## AMToast (`overlays/Toast.kt`)

`AMToast(item: AMToastItem?, onDismiss, anchor: AMToastAnchor = Center, modifier, hostContent)`. `AMToastItem(id, text, icon: ImageVector? = null, duration = 2000L)`. `AMToastAnchor` maps Center/Trailing/Leading → `BottomCenter`/`BottomEnd`/`BottomStart` (use Trailing when a FAB owns the bottom-end corner).

Pill: **capsule is `RoundedCornerShape(50)`, not `CircleShape`** (CircleShape doesn't scale on non-square bounds). Chrome: `amElevation(Low)` → `Surface.primary` fill → **unconditional `amHairline`**. Outer padding: **`navigationBarsPadding()` (clears the gesture nav bar / home indicator, iOS bottom safe area) then** `spacing.xl` bottom, `lg` horizontal. Inner padding: `md` horizontal, `sm + 2dp` vertical (`verticalPadBump = 2.dp` — keeps the single text line off the capsule curve). Optional icon 15dp tinted `Text.primary`; text `AMTheme.Type.secondary`, `maxLines = 1`, ellipsis. Toasts are deliberately **neutral — no semantic tint**; tinted feedback is `AMBanner`'s job. The pill carries `semantics { liveRegion = Polite }` so TalkBack announces it on appearance.

Dismissal: auto (`LaunchedEffect(item?.id)` + `delay(duration)`), tap (`detectTapGestures` — no ripple), swipe **down** past 30dp (`dismissThresholdCompact`). Presents with `slideInVertically(presentSpringIntOffset)` from `+fullHeight` + `fadeIn(presentSpringFloat)` — the fade rides the same present spring as the slide (not overlayFade) so they read as one motion. No blur, no scrim, no tap-catcher — host content stays interactive.

## AMSheet (`overlays/Sheet.kt`)

`AMSheet(isPresented, onDismiss, height = AMSheetHeight.Full, modifier, sheetContent, hostContent)` — `height` is a config param between `onDismiss` and `modifier`; `sheetContent` sits *before* the trailing `hostContent`. Bottom-anchored card, **top corners only** (`amSquircle(topStart = topEnd = radius.lg, bottomStart = bottomEnd = 0)` — continuous corners, not a plain `RoundedCornerShape`). Chrome: `amElevation(Medium)` → `Surface.primary` → **unconditional `amHairline`** → `clip(sheetShape)`. Grabber: **36×5dp** capsule filled `Icon.muted`, `spacing.sm` top padding. The card offset applies `.coerceAtLeast(0)` so the under-damped reject snap-back overshoot can't lift the card above its top edge. **No blur, no visual scrim** — the world stays visible; an invisible `amTapCatcher` fades in/out with `fadeSpec` (the RM-resolved `modalSpringFloat`, so the catcher fades on the same modalSpring as the card slide) *behind* the card (declared before it) and dismisses on outside tap. The card **sinks taps on its own chrome** via an unconditional `pointerInput(Unit){ detectTapGestures{} }` consumer (same rationale as `AMActionsOverlay` — a plain tap is not consumed by `amDragDismiss`, so without the sink a tap on the grabber/chrome falls through to the catcher and wrongly dismisses; drag-to-dismiss still works because the drag detector accepts a consumed down). The card also carries `semantics { dismiss("Dismiss") { onDismiss(); true } }` so TalkBack exposes a discrete Dismiss action (iOS `.accessibilityAction(.escape)`).

**`AMSheetHeight` (`@Immutable` enum, Content/Full) — how tall the card grows; the iOS twin is `IMSheetHeight`.** **Full is the default**: the card container gets `statusBarsPadding().fillMaxHeight()` so it fills the height stopping just below the top status-bar inset (grabber clears the status bar), content top-aligned (Column default), overflow clipped by `clip(sheetShape)`. **Content** adds neither — the card wraps its content, capped at the host `Box`'s max height and clipped. The Full default is deliberate: the sheet fills the screen unless the caller opts into `Content` sizing.

Safe area & keyboard: the inner **content** Column (not the card) chains `navigationBarsPadding().imePadding()`, so the fill extends to the physical screen bottom under both the nav bar and the keyboard while content clears the gesture zone and rides above the keyboard; a `spacing.xxl` Spacer pads below `sheetContent`. Order matters — inset consumption makes the pair resolve to `max(navBar, ime)` (navBar consumes its strip first, so `imePadding` subtracts it), never additive. The card chrome never shrinks; only content is pushed up.

Dismissal: tap-outside, drag down past `tokens.motion.dismissThreshold` (60dp) with live offset tracking (`dragOffset` keyed on `isPresented`, clamped `.coerceAtLeast(0)`), or **system back** (`BackHandler(enabled = isPresented)` from `androidx.activity.compose`). Motion routes through the house Reduce-Motion policy: `slideSpec = tokens.motion.resolvedFiniteOrNull(modalSpringIntOffset, LocalAMReduceMotion.current)` and `fadeSpec = tokens.motion.resolvedFinite(modalSpringFloat, …)` (the catcher fade — and the card's cross-dissolve under RM — ride the same modalSpring as the slide). Normal motion slides on `modalSpringIntOffset` (224/0.86); under Reduce Motion `slideSpec` is null and the card cross-dissolves in place via `fadeSpec` (no full-screen travel), mirroring iOS `imPresentationEdge(.bottom, reduceMotion:)`. **`resolvedFinite`/`resolvedFiniteOrNull`** are `AMTokensMotion` extensions in `tokens/Motion.kt` (alongside `resolved`/`resolvedOrNull`, and imported by most overlay/frame files) that return the `FiniteAnimationSpec<T>` the `AnimatedVisibility` slide/fade APIs require rather than the wider `AnimationSpec<T>` (both policy branches construct finite specs — a safe cast).

## AMBanner (`overlays/Banner.kt`)

`AMBanner(item: AMBannerItem?, onDismiss, modifier, hostContent)`. `AMBannerItem(id, title, message: String? = null, style = Info, duration = 4000L)`. `AMBannerStyle` is a `typealias AMBannerStyle = AMSemantic` (`tokens/Semantic.kt`, the canonical role→color+glyph axis; Info/Success/Warning/Destructive) — mirrors iOS `typealias Style = IMSemantic`. Tint comes from `style.color(tokens.semantic)` (resolves against `LocalAMTokens`, so subtree overrides re-tint) and `icon` from **icons-core only**: Info/CheckCircle/Warning, and **`Icons.Filled.Close` for Destructive** (icons-core has no octagon glyph — documented substitution).

Two independently animated layers, both `Alignment.TopCenter`:
1. **Top scrim** — `fillMaxWidth().height(220.dp)` vertical gradient of `Surface.primary`: opaque from 0% to 20%, fading to alpha 0 at 100%. Fades with `presentSpringFloat` (the same present spring as the card, not overlayFade); **non-interactive** (no handler — touches fall through to hostContent). Carries no inset, so it bleeds full-height under the status bar.
2. **Banner card** — `AMCard(padding = null)` + **`statusBarsPadding()` (lands the card below the status bar, iOS top safe area)** + outer padding (lg horizontal / sm vertical) + live `dragOffset` offset + `amDragDismiss(Up, 30dp)` + tap-to-dismiss + `semantics { liveRegion = Polite }` (TalkBack announces on appearance) + **unconditional `amHairline(amSquircle(radius.lg))`**. Row padded `spacing.md`: style icon 20dp tinted `style.color(tokens.semantic)`, then a Column spaced **2dp** (tighter than xs): title `AMTheme.Type.title` `Text.primary`, optional message `AMTheme.Type.caption` `Text.secondary`. Slides on `presentSpringIntOffset` from `-fullHeight` + `presentSpringFloat` fade (slide and opacity in lockstep).

Auto-dismiss identical to Toast (`LaunchedEffect(item?.id)`, 4s default).

## AMAlert (`overlays/Alert.kt`)

`AMAlert(item: AMAlertItem?, onDismiss, modifier, hostContent)`. `AMAlertItem(id, title, message?, confirm: AMAlertAction, cancel: AMAlertAction? = null)`; `AMAlertAction(label, role: AMButtonRole? = null, handler: () -> Unit = {})` — `role` reuses the enum from `frames/Toolbar.kt`.

Layering: hostContent Box gets `amBackdropBlur(animatedRadius)` (0 ↔ 20dp on **`snapSpringDp`** so the blur ramp tracks the card pop); above it, `AnimatedVisibility` chrome = `AMDarkScrim()` + a transparent **input blocker** (`detectTapGestures` consuming everything — **no outside-tap dismissal by design**; alerts force an explicit choice) + the centered card. The outer `AnimatedVisibility` owns null↔non-null: `scaleIn/Out(0.92)` + `fadeIn/Out`, **both on `snapSpringFloat`** so the pop and the backdrop-group fade read as one motion (iOS animates scale + opacity on `snapSpring`). An **inner `AnimatedContent(targetState = renderItem, contentKey = { it.id })`** wraps the card and replays the same scale/fade pop on an A→B item swap (`.id(item.id)` re-fire). Reduce Motion routes the scale through `resolvedFiniteOrNull ?: snap()` (appears at full scale) and the fade through `resolvedFinite`. **System back** (`BackHandler(enabled = item != null) { onDismiss() }`, `androidx.activity.compose`) is the one dismissal gesture — dismiss-*without*-action (runs no handler; the implicit cancel path). Outside taps still do nothing.

`AMAlertCard` (private) — **Alert card anatomy**: `AMCard(padding = PaddingValues(spacing.lg))` + unconditional `amHairline(amSquircle(radius.lg))`, `widthIn(max = 320.dp)` (iOS `maxCardWidth`), `padding(horizontal = spacing.xl)`, centered. Outer Column (`fillMaxWidth`) spaces the text block and buttons by `spacing.md`. Text block is an inner Column spaced `spacing.xs` with `padding(top = spacing.xs)`: title `AMTheme.Type.title` and message `AMTheme.Type.secondary`, **both `TextAlign.Center`** (via `.copy(textAlign = Center)` on the resolved style). Buttons are **full-width filled buttons** (not ghost): two-button = `AMSecondaryButton` (cancel) + `AMPrimaryButton` (confirm) in a `fillMaxWidth` Row `spacedBy(spacing.md)`, each `Modifier.weight(1f)` so they split the width evenly, cancel leftmost / confirm rightmost; single-button = one `AMPrimaryButton` `fillMaxWidth`. `role == Destructive` tints the button label `AMTheme.destructive` (red text on the filled card — handled inside the button String overloads, just pass `role`). **Handler contract: `action.handler()` runs first, then `onDismiss()`** — callers null their item in `onDismiss`, never inside handlers.

## AMLoadingOverlay (`overlays/LoadingOverlay.kt`)

`AMLoadingOverlay(isPresented, message: String? = null, modifier, hostContent)`. Blocking: blurred hostContent (`amBackdropBlur`, animated on `overlayFadeDp`) + `AMDarkScrim()` + a full-size input blocker that consumes taps silently — **no dismissal gesture of any kind**; the caller flips `isPresented` when work finishes. Centered **`AMSpinner(label = message ?: "Loading")`** (from `content/`) — the **non-compact** form, so the arc + caption sit in an `AMCard` and the label rides `AMSpinner`'s own `caption`/`Text.secondary` slot (iOS `.imSpinner` style; do NOT hand-roll the label). Chrome fades with `overlayFade` (Float) while the blur ramps on `overlayFadeDp` (Dp) — same 180ms values, lockstep by construction. **Modal a11y:** while presented the blurred hostContent Box carries `Modifier.semantics { invisibleToUser() }` and the chrome Box `isTraversalGroup = true` (iOS `.isModal`). **Paused-world chrome is token-locked**: blur radius is `AMTheme.Overlay.blurRadius` (20) with no public knob (iOS locked it too), so it reads identically everywhere. Both the blur ramp and the fade route through `tokens.motion.resolved(…, LocalAMReduceMotion.current)`, so under reduce motion they stay the gentle 180ms fade.

## AMActionsOverlay (`overlays/ActionsOverlay.kt`)

`AMActionsOverlay(isPresented, onDismiss: (() -> Unit)?, modifier, overlayContent, hostContent)` — `onDismiss` is required-but-nullable: **pass `null` for a non-dismissable overlay** (none of tap-catcher, catcher-drag, `BackHandler`, or TalkBack dismiss action is installed). The share-sheet-like "everything I can do here" layer; `overlayContent` is typically an `AMActionGrid` of 2–4-tile `AMActionGridButton` rows. **NOT a sheet.** `overlayContent` renders **bare** — no card, no fill, no hairline, no drag handle — inside a full-screen Box over the signature tint-free blur + dark scrim (the iOS twin is `IMModalBackdrop`). Tiles **keep their default `AMElevation.Low`** and self-card, floating free over the paused world (the `AMActionGrid`'s leading weighted spacer bottom-anchors them). **Paused-world chrome is token-locked**: blur radius `AMTheme.Overlay.blurRadius` (20), scrim alpha `AMTheme.Overlay.scrimOpacity` (0.4), no public knob (iOS locked them too).

**One-group opacity fade — no slide, no spring.** A single `AnimatedVisibility` (`fadeIn`/`fadeOut` on `overlayFade` via `resolvedFinite`) holds the scrim + catcher + `overlayContent` together, mirroring iOS's single `.transition(.opacity)` over the whole backdrop. The blur radius ramps 0↔`AMTheme.Overlay.blurRadius` on `overlayFadeDp` in lockstep. **Reduce motion** is a no-op here beyond the existing gentle fade — there's no spatial transform to collapse, so ActionsOverlay carries no slide/scale spring mirror at all (only `overlayFadeDp` for the blur ramp).

Layers inside the outer `Box(modifier)`:
1. **Blurred hostContent** — `amBackdropBlur(animatedRadius)`; while presented the Box also carries `Modifier.semantics { invisibleToUser() }` so TalkBack skips the paused world (iOS `.isModal`). The `LocalAMOverlayActive` provider wraps `hostContent()` here as always.
2. **Chrome group** — the one `AnimatedVisibility`, a `fillMaxSize` Box marked `isTraversalGroup = true` (focus stays inside), holding: `AMDarkScrim(opacity = scrimOpacity)`; then (if dismissable) a full-screen catcher; then `overlayContent()` rendered **on top**. Because bare content installs no pointer input on its empty regions, taps that miss the (clickable) tiles fall through to the catcher and dismiss; tile taps hit the tiles.

**Drag-to-dismiss lives on the CATCHER, not content** (content never moves — the key fix). The catcher is `Modifier.amTapCatcher { onDismiss() }` + a `detectVerticalDragGestures` block that is **end-evaluated**: plain-var accumulators (`netTranslation`, `travel`) sum the drag, and `onDragEnd` dismisses iff `travel >= dragActivationDistance` (a file-level `24.dp`, iOS `DragGesture(minimumDistance: 24)`) **and** `netTranslation > tokens.motion.dismissThreshold` (60dp). No `dragOffset`, no `amDragDismiss`, no live follow. The catcher also carries `semantics { dismiss { onDismiss(); true } }` (TalkBack dismiss = iOS `.accessibilityAction(.escape)`). **System back**: `BackHandler(enabled = isPresented && onDismiss != null) { onDismiss?.invoke() }` (`androidx.activity.compose`).

## AMFloatingActionsHost + LocalAMOverlayActive (`overlays/FloatingActions.kt`)

The scene FAB hub; the iOS twin is `imFloatingActions`. **Scene-root pattern:** every scene wraps its content **once** in `AMFloatingActionsHost` and puts its actions (including any Exit tile) in the `menu` slot as `AMActionGrid` rows.

**`AMFloatingActionsHost(isPresented, onPresentChange, alignment = AMFABAlignment.Center, bottomInset = 0.dp, enabled = true, offset: MutableState<Offset>? = null, accessibilityLabel = "Show actions", modifier = Modifier, menu, hostContent)`** — note `alignment` defaults to **Center** (the iOS scene-hub default), whereas a bare `AMFloatingActionButton` keeps its own `Trailing` default. Param order mirrors `AMActionsOverlay`: `modifier` then the two content slots (`menu`, then the trailing `hostContent`).

Structure: the host **is** `AMActionsOverlay(isPresented, onDismiss = { onPresentChange(false) }, modifier, overlayContent = menu) { Box(fillMaxSize){ hostContent(); FAB } }` — it does not reimplement the overlay. Z-order **content < FAB < menu overlay**: the FAB is the last child of the inner Box (draws over `hostContent`), and `AMActionsOverlay`'s blur + scrim + free-floating tiles draw over the whole thing. The FAB tap → `onPresentChange(true)`; the FAB is placed by wrapping `AMFloatingActionButton` in an `align(BottomCenter).fillMaxWidth().padding(bottom = bottomInset)` Box (the FAB itself owns horizontal `alignment` + its built-in `spacing.lg` insets).

**Overlays beat the FAB.** The FAB reads `overlayActive = LocalAMOverlayActive.current || isPresented` at the `AMActionsOverlay`-hostContent scope (where `AMActionsOverlay` already provides `isPresented || inherited`), so it sees its own menu AND any ancestor overlay in one read. When `overlayActive`, the FAB **fades to alpha 0** (via `graphicsLayer` on the wrapper) on `AMTheme.Motion.overlayFade` through `tokens.motion.resolved(…, LocalAMReduceMotion)` (instant under Reduce Motion) **and the click is gated**: `onClick = { if (interactive) onPresentChange(true) }` where `interactive = enabled && !overlayActive`. Gating the callback (not blocking the pointer) is the non-interactive lever while the FAB is still composed — during the fade and for a dimmed disabled FAB. Once the overlay fade settles at alpha 0 the FAB is dropped from composition entirely (the wrapper is gated `if (fabAlpha > 0f)`, mirroring iOS `fabLayer`'s `if !hidden`), so at rest under an overlay it holds neither its 56dp footprint nor a TalkBack focus node. The rest of the bottom strip stays pass-through so a non-modal ancestor (Toast/Banner) leaves the scene interactive.

**Disabled (`enabled = false`):** the whole FAB dims to `DISABLED_FAB_ALPHA` (0.4, private file-level const), the click is gated, and the wrapper carries `Modifier.semantics { disabled() }` so TalkBack announces it disabled rather than an actionable-but-inert button. This mirrors iOS `.disabled()` (whole-view dim), **not** `AMToolbarButton`'s glyph-only greying — the public `AMFloatingActionButton` exposes no disabled glyph-tint hook and this host must not modify it.

**`LocalAMOverlayActive: CompositionLocal<Boolean>` (public, default false)** — the Compose counterpart of iOS `IMOverlayActivePreferenceKey`. iOS reports overlay presence bottom-up as a preference; on Android overlay presenters are HOSTS that WRAP content, so the signal flows top-down: each host provides `own || inherited` into its `hostContent` (see the provider note under *Overlay host pattern*), and nested hosts OR. Declared **`compositionLocalOf` (NOT static)** — the value flips at runtime as overlays present, so only readers recompose. Because the hub reads it **inside** the overlay chain (below every wrapping host), a FAB hub placed ABOVE an `AMPanelHost` does not see that panel's signal — panels are navigation and keep the hub on top; only a FAB in the background scene below a panel fades, which is correct since the panel covers it.

Demo: exercised as the scene-root hub across the Screens scenes — e.g. `demo/.../scenes/auth/AuthScene.kt`, `demo/.../scenes/calendar/CalendarScene.kt`, `demo/.../scenes/gallery/GalleryScene.kt`. In `AuthScene` the overlay nesting `AMLoadingOverlay → AMBanner → AMToast → AMFloatingActionsHost` wraps the hub so any of those overlays presenting keeps the FAB faded out — the on-screen proof of `LocalAMOverlayActive`.
