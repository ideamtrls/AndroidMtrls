# Lists

Rows and the lists made of them, all on Material's `ListItem` at the row recipe's rhythm (`Layout.md`): `AMListRow` (a flat row), `AMListCard` (a list item that is a card), `AMLabeledContent` (a label and its value), `AMSwipeableRow` with `AMSwipeAction` (one full-swipe action per direction, on `SwipeToDismissBox`), and the two reorderable lists, `AMReorderableRowList` and `AMReorderableCardList`, one engine with drag handles, a press-and-hold lift, auto-scroll and TalkBack's "Move up" and "Move down", over a `LazyColumn` that scrolls itself or, in a scrolling page, a plain column that scrolls with the page.

## Rows on `ListItem`

All three row kinds pass `AMRowDefaults.colors()`, `shapes()` and `contentPadding` (or the card's variant of it), so they follow the row recipe and its heights (`Layout.md`). Text wraps and the row grows; Material's list item centers the leading and trailing content beside short content and top-aligns it beside tall content. Stack rows with `AMDivider(inset = spacing.lg)` between them. Each row claims its container's custom actions onto its own node (below) and provides `LocalAMRowActions` null to its slots.

### `AMListRow` — `ListRow.kt`

- String: `AMListRow(title, modifier, subtitle: String? = null, leadingContent?, trailingContent?, selected = false, onClickLabel: String? = null, onClick: (() -> Unit)? = null, enabled = true)`. Slot: `AMListRow(modifier, leadingContent?, supportingContent?, trailingContent?, selected, onClickLabel, onClick?, enabled, content)`, the headline last. The string form delegates; a null or empty subtitle shows no supporting line.
- **The tap's name.** `onClickLabel` is what TalkBack says after "double-tap to" ("Play", "Open album"); Material's list item takes no click label, so internal `Modifier.rowClickLabel(label, onClick, enabled)` (in `ListRow.kt`) puts `semantics { onClick(label) { onClick(); true } }` on the list item's own node, where it replaces Material's unlabeled click action with the same tap, labeled. Nothing without a label or a tap, or while disabled. `AMListCard` takes the same `onClickLabel`, before its `onClick`.
- **Surface**: `fillMaxWidth().amFlatSurface()`: a strip edge to edge in the app's setting when it stands on its own (`AMTheme.Surface.primary` in a solid app; in a frosted app, frosted on the backdrop and the tint on a sheet; `Layout.md`), nothing inside a card, so the card's rounded surface shows. **Its text lies on the strip** (or the card), off any art around it: the strip is the `ListItem`'s own node, composed where the row stands, so each slot goes in `ProvideAMOnSurface` (internal `slotOnSurface`, in `ListRow.kt`, which `AMListCard` shares) and the row colors are read as on the strip (`readOnSurface { AMRowDefaults.colors() }`); the subtitle takes the frosted secondary on a frosted strip.
- **Taps**: no `onClick` → Material's non-interactive `ListItem` (it only draws); with one → the clickable `ListItem`, ripple and button semantics. Long-press actions come from `Modifier.amHoldable` on the row; swipe actions from wrapping it in `AMSwipeableRow`. There is no drill-down chevron: Android rows signal a tap by their ripple, and a caller who wants a trailing glyph passes it in `trailingContent`.
- **`selected`** draws the selection ring, `amHairline(RectangleShape, width = AMTheme.selectionRingWidth)` in `selectionRing`, inside the row's edges, and sets `selected` semantics. The row never tints.
- `enabled` goes through `resolveEnabled` to the list item, which dims a disabled row and stops its taps.

### `AMListCard` — `ListCard.kt`

- String: `AMListCard(title, modifier, subtitle?, leadingContent?, trailingContent?, onClickLabel?, onClick?, enabled)`. Slot: `AMListCard(modifier, leadingContent?, supportingContent?, trailingContent?, onClickLabel?, onClick?, enabled, content)`; `onClickLabel` names the tap for TalkBack, as on `AMListRow`. `supportingContent` takes a row of tags or a card's actions as well as text.
- The `ListItem` wears `fillMaxWidth().amCard(elevation = elevation)`: `shapes.large`, the `Low` shadow, its ripple clipped to the corners, in the app's setting as every card (`Layout.md`): solid with the dark hairline in a solid app; in a frosted app, frosted on the backdrop and the tint on a sheet. Content padding is the row recipe's, plus `LocalAMReorderHandleInset` at the end.
- **Its text lies on the card**, off any art around it. The card is the `ListItem`'s own node, composed where the list card stands, so the card isn't wrapped: each slot is (`ProvideAMOnSurface`), and the row colors are read as on the card (internal `readOnSurface { AMRowDefaults.colors() }`), so the supporting line takes the frosted secondary in a frosted app (`Foundations.md`).
- **In a reorderable card list** it reads `LocalAMReorderHandleInset` (the handle's 24 dp plus `spacing.md`), so its text stops short of the list's handle, and `LocalAMReorderLifted`, raising its card to `AMElevation.Medium` while it's dragged or settling. It resets both for its own slots.
- Stack list cards `spacing.md` apart.

### `AMLabeledContent` — `LabeledContent.kt`

- String: `AMLabeledContent(label, value: String, modifier)`. Slot: `AMLabeledContent(label, modifier, value: @Composable () -> Unit)` for a value that isn't text (a status tag).
- A non-interactive `ListItem` whose headline slot holds both, laid out by private `LabeledContentLayout` (a two-content `Layout`), so the list item reads label and value as one node: the label (`bodyLarge`, `onSurface`) at the start, then `spacing.lg`, then the value under `ProvideTextStyle(bodyLarge, TextAlign.End)` and `LocalContentColor = AMTheme.secondaryText` (`onSurfaceVariant`, the frosted secondary on frost), so it reads as a value, not as Material's small trailing note.
- **The shorter text keeps its line; the other wraps.** The label is laid out at `labeledContentLabelWidth` (unit-tested) from both texts' one-line widths (max intrinsic) and longest words (min intrinsic), in the room (the row less the gap): both fit, the label takes its own width; otherwise the shorter one keeps its line while it's no wider than half the room and the other wraps in the rest (the value checked first, so a short value beside a long label stays whole: "Visa ending 4242" beside "Charged automatically on the renewal date"); both wider than half, half the room each. Then the label leaves the value at least its longest word and keeps at least its own (its own wins), never wider than the room. The value gets the rest of the row, is placed at the end, and wraps onto end-aligned lines ("214 Van Brunt St, Brooklyn, NY 11231" beside "Billing address"). Nothing stacks at large text.
- **Vertical alignment**: the two first baselines line up when both have one (text, a tag); otherwise they center on each other.
- `fillMaxWidth().amFlatSurface()`, like `AMListRow`, its label and value lying on the strip (`ProvideAMOnSurface` around the layout, the row colors through `readOnSurface`). It takes no taps and has no `enabled`.

## Swipe actions — `SwipeableRow.kt`

```kotlin
AMSwipeableRow(
    startAction = AMSwipeAction("Archive", archiveIcon, removesRow = true) { archive(message) },
    endAction = AMSwipeAction("Delete", deleteIcon, AMSemantic.Destructive, removesRow = true) { delete(message) },
) { AMListRow(message.sender, subtitle = message.subject) }
```

- **`AMSwipeAction(label, icon: Painter, tint: AMSemantic? = Info, removesRow = false, onClick)`**, `@Immutable`. `label` is TalkBack's custom action; `icon` shows on the band; `tint` colors it (the band in `tint.color`, the glyph in `tint.onColor`; `Destructive` is the scheme's `error`). `tint = null` is the neutral action, neither a status nor a removal (mute, snooze): the band in `surfaceContainerHighest`, the glyph in `onSurface`, the neutral tag's pair, gray in both modes. `removesRow` says the action takes the row away.
- **`AMSwipeableRow(modifier, startAction?, endAction?, enabled, content)`**: one action per direction, the Android way. `startAction` sits at the row's start and a swipe toward the end reveals it (rightward in left to right); `endAction` the reverse. A null side doesn't swipe; with neither, gestures are off. More actions belong in a ⋮ menu or a press and hold.
- Built on internal `SwipeBox`, which the reorderable row list shares: Material's `SwipeToDismissBox` on `rememberSwipeToDismissBoxState(positionalThreshold = half the row)` (`SwipeCommitFraction`, 0.5), so a release past half the row or a fling acts and anything shorter springs back. `enableDismissFromStartToEnd` / `EndToStart` follow which actions exist; `gesturesEnabled` is `enabled` and at least one action.
- **After the swipe**: `onDismiss` (after the slide-away settles) runs the action's `onClick`; an action that `removesRow` leaves the row swiped off, showing its band, until the caller drops the item; any other `reset()`s the row back.
- **The band** (`SwipeBand`): drawn only while the row is off center, for the action on that side, in its tint's colors or the neutral pair, filling the row but clipped to the strip the content has uncovered (`swipeRevealSpan(offset, width, rtl)`: the content's physical shift is the offset in left to right and its negation in right to left). So a row lying transparent on a card shows nothing behind it at rest, and the card's clip rounds the band at its corners. The glyph sits `spacing.lg` in from the edge the swipe started from. No label: the glyph carries it.
- **Haptic**: `GestureThresholdActivate` each time the target value leaves `Settled` (the release would act).
- **TalkBack**: `swipeAccessibilityActions` turns each action into a `CustomAccessibilityAction` running its `onClick`, offered through `RowActionsContainer`. None while disabled.

## The reorderable lists — `ReorderableLists.kt`, `ReorderEngine.kt`

```kotlin
val queue = rememberSaveable(saver = …) { mutableStateListOf(*episodes) }
AMReorderableRowList(queue, key = { it.id }, onMove = { from, to -> queue.add(to, queue.removeAt(from)) }) { episode ->
    AMListRow(episode.title, subtitle = episode.show)
}
```

- **`AMReorderableRowList(items, key, onMove, modifier, state = rememberLazyListState(), startAction: (T) -> AMSwipeAction? = { null }, endAction = { null }, holdToLift = true, enabled, content: @Composable (T) -> Unit)`**. Each row: a `RowActionsContainer` (move actions plus the swipe actions) around a `SwipeBox` around a `Row(fillMaxWidth().amFlatSurface())` of the content (`weight(1f)`, in `ProvideAMOnSurface` and `ProvideAMSurfaceStyle(Flat)`, so it lies on the row's strip and the `AMListRow` in it draws no strip of its own: one strip per row, never two) and the handle, `spacing.lg` from the end, so the handle travels with a swipe. Rows lie flat on whatever holds the list; a lifted row comes up as a floating surface: `amElevatedSurface(shapes.large, AMElevation.Medium, lifted = true).clip(shapes.large)`, in the app's surface setting and never the tint, so the rows it's dragged across never show through it (`Foundations.md`): solid with the dark hairline in a solid app; in a frosted app frosted as on the backdrop even inside a card or on a sheet, over the art under it (the slice the card shows there, so it reads as a piece of the card raised, followed as it moves) or frost over the page color with none (a sheet's queue, a plain page), opaque, with the frosted edge. Its swipe is off while lifted. Pair it with `AMListRow`. It takes the same two forms as the card list (below), with no content padding in either: in a scrolling page a card on its modifier (`Modifier.amCard()`, frosted over art in a frosted app, the rows carrying `amArtRow`) is as long as its rows, swipes and TalkBack's actions unchanged.
- **`AMReorderableCardList(items, key, onMove, modifier, state, holdToLift = true, enabled, content)`**. Each cell carries `spacing.lg` side and `spacing.xs` vertical margins (the page gutter, so the list runs edge to edge and its cards land on the gutters; in the catalog it sits on a `Wide` stage). The handle overlays the card's trailing edge, `spacing.lg` in; the cell provides `LocalAMReorderHandleInset` and `LocalAMReorderLifted` for `AMListCard`. Custom card content keeps its trailing edge free.
- **Two forms, both lists.** Each list is internal `ReorderableList`, a `BoxWithConstraints(modifier, propagateMinConstraints = true)` that picks its form from the height it's measured with:
  - **Bounded** (a screen, a weight, `heightIn(max = …)`): the lazy `ReorderableColumn` on `state`, scrolling itself and taking its content's height up to the bound; the card list adds `spacing.md` content padding above and below for the first and last cards' shadows.
  - **Unbounded** (inside `Modifier.verticalScroll`, or a lazy list's item): `ReorderablePageColumn`, a plain column as tall as its items (no extra padding: nothing clips the cards' shadows) that scrolls with the page, a lifted item auto-scrolling the page. `state` isn't used. Every item is composed, so it's for lists of a page's length.
- **State is the caller's.** `onMove(from, to)` asks for one step at a time, as the drag passes each neighbor, each from the order the step before left. The list shows each step at once in its own order and shows `items` again once they've taken the last step, so the caller makes the same moves in order, at once or later (a database write per step, back through its updates). `key` must be stable and `Bundle`-saveable. `enabled` goes through `resolveEnabled`; a disabled list takes no drags or swipes, offers no actions and dims its handles (`onSurface` at `DisabledAlpha`, 0.38).
- **Hold to lift.** `holdToLift` (both lists, default true) lets a press and hold anywhere on an item lift it. A lift and a `Modifier.amHoldable` on the item answer the same long-press timeout, so an item with its own hold takes `holdToLift = false`: it lifts from the handle only, and a hold on the rest of the item opens the item's spotlight without the item also lifting.

### The engine — `ReorderState` over a `ReorderLayout`

- **Two layouts, one state machine.** `ReorderState` reads the items through internal `ReorderLayout`: `item(key)`, `itemAt(index)`, `itemUnder(y)` (each a `ReorderItem(key, index, offset, size)` in the list's frame), `window()` (the span a lifted item stays inside), `canScroll(velocity)`, `scrollBy(delta)`, `drift()`, `pointerSynced()` and `beforeMove(from, to)`. `rememberReorderState` writes its settings (`onMove`, `enabled`, `holdToLift`, `rtl`, haptics, the settle spec `motionScheme.defaultSpatialSpec()`, the handle and edge zones and the top scroll speed in pixels) in a `SideEffect`.
  - **`LazyReorderLayout`** (the `LazyColumn`): positions from `layoutInfo.visibleItemsInfo`, in the frame from the start of the content area (a touch converts by `viewportStartOffset`); the window is the viewport; `scrollBy` scrolls the list (the items move, the frame doesn't); `beforeMove` pins the scroll by index (`requestScrollToItem`) when the first visible item takes part.
  - **`PageReorderLayout`** (the page column): positions from the column's own measure, in the column's frame, behind a version counter (state) so a layer that reads them follows the layout; the window is what's visible of the column, its bounds inside every clipping parent (`findRootCoordinates().localBoundingBoxOf(column, clipBounds = true)`, the page's viewport among them); `canScroll` only toward an edge where more of the list is hidden; `scrollBy` goes to the page through a `NestedScrollDispatcher` (`dispatchPreScroll` then `dispatchPostScroll`, `NestedScrollSource.UserInput`, so a collapsing top app bar takes its share first) and returns what was consumed, which is how far the whole column moved under the still finger; `drift()` measures the column's real move in the root against that expectation each frame and returns the difference, so the lifted card stays under the finger whatever took part in the scroll.
- `ReorderableColumn(items, key, onMove, modifier, listState, enabled, contentPadding, handleZone, holdToLift, cell)` is the `LazyColumn` (`itemsIndexed` keyed by `key`); `ReorderablePageColumn(items, key, onMove, modifier, enabled, handleZone, holdToLift, cell)` is the page form, a `Layout` stacking the items (each in `key(itemKey)`) with `nestedScroll(…, dispatcher)`. `cell(item, lifted, moveActions)` (`ReorderCell`) draws an item.
- **Placement per item** (`reorderPlacement`): the lifted item `zIndex(2f)` with `graphicsLayer { translationY = liftedOffset() }`; the settling item `zIndex(1f)` with the settle `Animatable`'s value. Every other item: in the lazy list, `animateItem` (placement `defaultSpatialSpec`, fade in and out `defaultEffectsSpec`), so neighbors slide out of the way and removed items fade as the rest close up; in the page column, a slide of its own (`PageReorderLayout.place`: an item whose slot moved since the last measure starts from where it was, an `Animatable` to 0 on `defaultSpatialSpec`, kept as state read in placement), so neighbors slide aside; items that come and go just appear and leave as the rest slide.
- **Gestures** (`reorderGestures`, a `pointerInput` on the list itself, so positions stay in the list's frame while items move and the list scrolls): each touch is watched in the **Initial** pass, ahead of the items' clicks and swipes and the list's scroll, and nothing is taken until a drag starts. A down in the trailing `handleZone` (row list: `lg + 24 dp + lg`; card list: `lg + lg + 24 dp + lg`, the end mirrored in right to left) lifts once the touch passes the touch slop (`GestureThresholdActivate` haptic); anywhere else it lifts once held still for the long-press timeout (`LongPress` haptic), and moving past the slop first leaves the touch to scrolling and swiping. Without `holdToLift`, a down off the handle is left alone from the start. From the lift on, every change is consumed until the finger lifts, and `drop()` runs in a `finally`.
- **Following the finger**: the item's top is its slot's offset at the lift plus the finger's travel, kept inside the list's window (`clampLiftedTop`), minus its current slot's offset: a move or a scroll changes the slot, never the item's place under the finger. In the page column a scroll moves the whole frame, so the finger's place in it grows by the scroll consumed (and any `drift()`), set back to the true place on each touch event.
- **Trading places** (`moveIfPassed`, after each drag event and each auto-scroll step): `reorderStep` returns +1 once the lifted item's bottom passes the middle of the item below, −1 once its top passes the middle of the item above. Each neighbor's own middle keeps a short and a tall item from trading back and forth. Nothing moves while the last step hasn't reached the layout (the lifted item's laid-out index isn't its place in the order shown), a frame at most. When the first visible item takes part, `requestScrollToItem(first, offset)` pins the scroll by index so the list doesn't jump. Each step goes through `ReorderState.move` and ticks `SegmentTick`.
- **The order shown** (`ReorderOrder`, plain, behind `ReorderState`'s version counter): each column maps `items` to keys, shows `state.shown(keys)` (the items rearranged by key, or `items` itself when nothing's pending) and passes the keys to `state.observe` in a `SideEffect`. `move(from, to)` takes a step in the order shown at once (recomposing the column), then calls `onMove`. The order keeps the order before the first step and after each step since; the caller's keys, as they come in, are matched against them on the keys they share, from the step last matched on (the caller takes the steps in order, conflated or not): matching an earlier step, the last step's order shows, with any item the caller added or removed meanwhile keeping its place (`reorderArrange`); matching the last step, or none (the caller moved on), the steps go and `items` shows.
- **Auto-scroll**: while lifted, a frame loop (`withFrameNanos`) scrolls by `reorderAutoScrollVelocity` × frame time: only toward the edge the item has traveled to, once it's within the edge zone (`ReorderEdgeZone`, 64 dp, at most a quarter of the window), faster with depth up to `ReorderMaxScrollVelocity` (800 dp/s). The lazy list scrolls itself; the page column scrolls the page, and only while the list runs on past that edge of the visible window.
- **Drop**: the lifted item becomes the settling one, its `Animatable` snapped (undispatched, in the same frame) to where it was and animated to its slot; `GestureEnd` haptic. Lifting the settling item again picks it up where it is.
- **TalkBack**: `reorderAccessibilityActions` gives each item "Move up" (not the first) and "Move down" (not the last), a step `move(index, index ∓ 1)` in the order shown. The handle (`ReorderHandle`, `am_ic_drag_handle` in `onSurfaceVariant`, no description) is skipped.

## Row actions for TalkBack — `RowActions.kt`

A container's custom actions (the swipe actions, the move actions) belong on the row's own focusable node, the one reading its text, so the row stays one stop with its actions one step away. The container can't reach that node, so it hands them down:

- `RowActionsContainer(actions, modifier, content)` remembers a `RowActions(actions, claims)` and provides it as `LocalAMRowActions` and `LocalAMRowHold`. `RowActions.actions` (snapshot state, updated in a `SideEffect`) is the container's own list; nested in another container it takes the outer actions first and claims them. `RowActions.held` (snapshot state) is a hold's actions on the row (`Modifier.amHoldable` puts them there, `Overlays.md`), and **`all` = `held + actions`: the hold's tiles, then the moves, then the swipes**, the one list TalkBack finds. While no row has claimed it, the container carries `all` itself, `semantics(mergeDescendants = true)` around its content (only when there's something to carry; whether a hold added any is a `derivedStateOf`, so a hold's update doesn't recompose it).
- `claimRowActions()`, called by `AMListRow`, `AMListCard`, `AMLabeledContent` and the bar form of `AMProgressView` (`Feedback.md`), counts a claim (a `DisposableEffect`) and returns `Modifier.semantics { customActions = slot.all }` (when non-empty, read inside the block, so a hold arriving later updates it) for the list item, joining its merged node.
- Rows provide `LocalAMRowActions` null to their slots, so nothing inside claims again, but leave `LocalAMRowHold`, so a hold on the row's own modifier (composed inside the row) still finds the container.
