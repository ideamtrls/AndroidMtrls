# Account scene

The account side of **Margin**, a made-up read-later app: onboarding, sign-in and two-factor, stand-in requests and their cancellation, the profile and settings. Its entry is `accountScene` ("Account", "Onboarding, sign-in, and settings", `ic_account_circle`), last in `ShowcasePages.entries`. Nothing pushes: signed out, the phases fade in place; signed in, the remote swaps Profile and Settings. The shared scene rules are in `DemoScenes.md`.

## The root — `AccountScene()`

- `rememberCoroutineScope()`, then the model: `rememberSaveable(saver = saver) { AccountModel(scope) }`, its saver `remember(scope) { AccountModel.saver(scope) }`. A `DisposableEffect` cancels pending work when the scene leaves the composition. `showsRemote` is its own saved flag.
- The plain `AMScene`, its remote in `floatingActions`: `AMFloatingActions(contentDescription = "Actions")`. Its content: the signed-in roots or the signed-out flow, then `AccountOverlays`.
- **Signed out** (`AccountSignedOut`): a `Box(fillMaxSize().amCrossfade(phase))` showing the phase, so each step fades in as the old one leaves. A `NavigationBackHandler` (navigationevent-compose), enabled off the intro, calls `goBack()`: system back walks the steps exactly as each step's back button does, and on the intro back falls through and leaves the scene.
- **Signed in** (`AccountSignedIn`): `AMKeepsPlace(current = currentView, landing = Profile)` over `AccountProfile` and `AccountSettings`, so each comes back where it was left (its scroll saved and restored), and back from Settings swaps to Profile before back leaves the scene.
- **Overlays** (`AccountOverlays`), composed inside the scene so the remote's button fades under them: the Help, Reset password and Edit profile `AMSheet`s (all `AMSheetHeight.Content`, titled "Help", "Reset password", "Edit profile"); the sign-out `AMAlert` (a remembered `AMAlertItem`: "Sign out?" / "Your reading list stays saved to your account.", Cancel and a destructive Sign out that calls `signOut()`), shown while `confirmsSignOut`; `AMLoadingOverlay(isLoading, loadingMessage)`; `AMBanner(banner)`, whose tap calls `fillCode()` then `verify()` (the only banner is the texted code); `AMToast(toast)`. No sheet carries the discard guard.

### Page frames

- **`AccountStepPage(title, onBack, subtitle = null, content)`**, every phase after the intro: a `Scaffold` on the page color under one header, `AMPageHeader(title, navigationIcon = back, exitUntilCollapsedScrollBehavior)`: Material's large top app bar with the back button (`AMToolbarButton`, `ic_arrow_back`, "Back", calling `onBack`) in its top row and the step's title under it, collapsing as the page scrolls. The body is a scrolling column inset by the page gutter, `spacing.sm` at the top: the subtitle (`bodyMedium`, `onSurfaceVariant`) as its first line, then the content, `spacing.xl` apart. The scaffold's content insets include the keyboard (`contentWindowInsets ∪ WindowInsets.ime`), and the column ends `AccountFabClearance` above the navigation bar.
- **`AccountPage(title, actions = null, content)`**, each signed-in view: a `Scaffold` under `AMPageHeader(title, actions, exitUntilCollapsedScrollBehavior)`, over a scrolling column inset by the page gutter, `spacing.sm` at the top, blocks `spacing.xl` apart, ending `AccountFabClearance` above the navigation bar.
- **`AccountFabClearance`** = 88 dp: the button's 56 dp with `spacing.lg` under and over it.

## The model — `AccountModel`

A plain `@Stable` class of Compose state, built on the scene's coroutine scope.

- **Flow**: `phase: AccountPhase` (`Intro`, `SignIn`, `CreateAccount`, `TwoFactor`, `Setup`; `SignIn` and `CreateAccount` are the credentials step in its two modes), `mode` (the credentials mode last run: it decides where a verified code goes and where back from two-factor lands), `isSignedIn`, `currentView: AccountView` (`Profile`, `Settings`). `begin(mode)` opens the credentials step in a mode, from the intro or the step's own switch.
- **Account**: `TextFieldState`s `email` ("ada@example.com"), `password`, `code`, `name` ("Ada Lovelace"); `interests: Set<String>` (Science, History, Books). Derived: `firstName`, `canSubmitCredentials` (email not blank and a password), `isCodeComplete` (exactly six digits 0–9), `orderedInterests` (in `AccountInterest.All` order). `AccountModel.CodeInput` is the code field's `InputTransformation`: whatever is typed or pasted, the field keeps its first six digits 0–9 before it shows, the rule `isCodeComplete` checks.
- **Settings**: `pushAlerts` on, `emailDigest` off, `mentionsOnly` off, `readerFont: AccountReaderFont` (`Serif`, `Sans`, `Mono`, each with a `title`) Serif, `privateAccount` off, `showActivity` on.
- **Overlays**: `banner`, `toast`, `isLoading` and `loadingMessage`, `showsHelp`, `showsForgotPassword`, `showsEditProfile`, `confirmsSignOut`, and `resendSecondsLeft`.
- **Requests are stand-ins**: coroutines in the scene's scope. `submitCredentials()` (ignored while loading or incomplete, so a double tap advances once) shows "Signing in…" or "Creating account…" for 1.2 s, then empties the password, enters `TwoFactor` and texts a code. `sendCode()` sets `resendSecondsLeft` to 30 and launches the code delivery: after 1.5 s the banner "Your code is 482 913" / "Tap to fill it in" (Info, 8 s), and a one-second countdown. `resendCode()` texts again once the countdown is at zero (on two-factor, not loading). `verify()` (ignored off two-factor, once signed in, while loading or with an incomplete code) shows "Verifying…" for 0.8 s, then cancels pending work, empties the code and, by `mode`, signs in (`currentView = Profile`, toast "Signed in") or enters `Setup`. `finishSetup()` runs once and signs the new account in (toast "Welcome, <first name>"). `fillCode()` fills the texted code. `sendResetLink(address)` (the Reset password sheet) writes the address to `email`, closes the sheet and toasts "Reset link sent to <address>".
- **Cancellation**: the request in flight and the code delivery are `Job`s. `cancelPendingWork()` cancels both, clears `isLoading` and the banner. It runs on every back step, once a code verifies, on sign-out, from the Exit tile, and when the scene leaves the composition (whose scope cancellation stops everything anyway), so no banner or toast lands on another screen.
- **Back**: `goBack()` steps the credentials step to the intro (emptying the password) and both two-factor and setup to the credentials step in `mode` (emptying the code: setup's code is already used, so stepping back to two-factor would only text another).
- **Signed in**: `saveProfile(name, interests)` commits the Edit profile draft, closes the sheet and toasts "Profile updated"; `confirmSignOut()` raises the alert; `signOut()` cancels pending work, empties password and code, returns to the intro and toasts "Signed out". The profile and settings outlive a sign-out.
- **Saved** (`AccountModel.saver(scope)`, a `mapSaver`): the phase and mode, signed in and the current view, email, code, name and interests, every setting, and which sheet or alert is up. The password and anything in flight aren't kept; a restored two-factor step offers "Resend code" at once.

- **Credentials** (`AccountSignIn`): "Sign in" / "Welcome back. Your reading list is waiting." or "Create account" / "Start free, with 5 GB for everything you save."; one card of fields padded `spacing.lg`, `AMTextField` "Email" (email keyboard, no capitals or autocorrection, Next) over `AMSecureField` "Password" or "Create a password" (Done submits), `spacing.md` apart with no divider, since each outlined field carries its own outline; the full-width main button ("Sign in" / "Continue", disabled until both fields hold text); then text buttons (`Ghost`): "Forgot password?" at the start and "Create account" at the end when signing in, a centered "I have an account" when creating.
- **Reset password sheet** (`AccountForgotPasswordSheet`): a centered `bodyMedium` line ("Enter the email on your account and we'll send a link to choose a new password."), an "Email" field (a draft of the account's email; Send sends) in a card padded `spacing.lg`, and `AMFormActions { "Send link" }`, disabled while blank.
- **Two-factor** (`AccountTwoFactor`): "Two-factor" / "We sent a six-digit code to your phone ending in 42."; the "Code" `AMTextField` in a card padded `spacing.lg`, with the number keyboard and `AMTextFieldAutofocus.CaretAtEnd` (Done verifies), kept to six digits by `inputTransformation = AccountModel.CodeInput`, so a dropped character never shows; full-width "Verify", disabled until six digits; a centered text button "Resend code (0:30)" counting down, disabled while it runs, then "Resend code".
- **Setup** (`AccountSetup`): "Set up your profile" (no subtitle); a card holding an `AMProgressView` Bar, "Last step" at two thirds with "Step 3 of 3"; then `AccountSetupForm` on the model's name and interests, "Finish".
- **`AccountSetupForm(name, interests, onInterestsChange, actionTitle, onSave)`**: a row of `AMAvatar(null, name, Large)` (its initials follow the typing; hidden from TalkBack) beside the "Your name" `AMTextField` (words capitalized, no autocorrection, Done) in a card padded `spacing.lg`; `AMSectionHeader("Interests")` over a many-choice `AMChipGroup` of `AccountInterest.All` (Technology `memory`, Science `science`, History `account_balance`, Design `palette`, Business `monitoring`, Books `menu_book`, Food `restaurant`, Travel `flight`; a chosen chip shows Material's check); then `AMFormActions` with the action, disabled while the name is blank, which trims the name before `onSave`. Blocks `spacing.xl` apart.
- **Profile** (`AccountProfile`, the signed-in landing view): `AccountPage("Profile")` with `SceneAppearanceButton()` as its header action; one card padded `spacing.lg` (`AccountProfileCard`): a `Large` avatar (hidden from TalkBack) beside the name (`titleLarge`) over the email (`bodyMedium`, `onSurfaceVariant`), then the interests as neutral `AMTag`s with their glyphs in an `AMFlowLayout`, read as one element "Interests: Science, History, and Books" (`ListFormatter`), or with none a line inviting some; a full-width "Edit profile" (Secondary); "This month" (`AMSection` Rows: `AMLabeledContent` Saved 128, Read 42, Highlights 17); "Recently read" (`AMSection` Rows: four bare `AMListRow`s, title over "source · minutes", such as "The Quiet Web · 6 min", taking no taps since nothing opens an article).
- **Edit profile sheet** (`AccountEditProfileSheet`): `AccountSetupForm` on a saved draft (`rememberTextFieldState` and `AccountInterestsSaver`) seeded from the model each time the sheet opens, in a scrolling column padded `spacing.lg`; "Save" commits it, any other close drops it.

## The remote

Signed out: Help, Exit. Signed in: Profile (`ic_account_circle`), Settings (`ic_settings`) over Help (`ic_help`), Exit (`ic_logout`). Profile and Settings are view tiles: the current one is `active`; a tap closes the menu, then sets `currentView` inside `amInstantSwitch`. Help closes the menu and opens the Help sheet. Exit closes the menu, cancels pending work and calls `LocalCatalogNavigator.current.back()`.

## Reaching each screen

From the scene's landing view (the intro): Sign in → the credentials step (Create account → its other mode; Forgot password? → the Reset password sheet). Type a password, Sign in → two-factor; the code banner comes down after 1.5 s, and tapping it verifies → Profile. From the intro, Create account → type a password, Continue → two-factor → the banner → Setup → Finish → Profile. Signed in, the remote's Settings → Settings; Help → the Help sheet; Edit profile → the Edit profile sheet; Sign out (Settings) → the alert.
