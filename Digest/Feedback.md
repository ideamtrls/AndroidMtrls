# Feedback

How the UI tells the user what's happening: `AMBanner` (a floating surface at the top of its window that dismisses itself and swipes up) with `AMBannerHost`, `AMToast` (Material's snackbar without an action, its container in the app's surface setting) with `AMToastHost` (the scene root, `AMScene`, carries both hosts, and every `AMSheet` both, which take over while it's up), `AMLoadingOverlay` (a dialog window that blocks while work runs: Material's circular indicator on a card), `AMEmptyState` (a glyph, title, description and actions lying on the page), `AMSkeleton` and `Modifier.amShimmer()` (shimmering placeholder shapes, and a text's placeholder at its exact size), `AMProgressView` (Material's circular or linear indicator, labeled, as `Spinner`, `Glyph` or `Bar`), and `AMPullToRefreshBox` (Material's pull to refresh, which reopens a collapsed page header before it pulls).

## Banners and toasts: a host per window

A banner or a toast belongs to its window, not to the composable that asks for it. So each kind comes as two pieces:

- **The host** (`AMBannerHost`, `AMToastHost`): `(modifier, content)`. One sits at the root of each screen that shows them, filling it. **The library places them**: `AMScene` (`Navigation.md`) mounts the internal `BannerHost` and `ToastHost` at its root, so a scene's banners come down at the top of the screen and its toasts up at the bottom; `AMSheet` (`Overlays.md`) wraps its title and content in a banner host and a toast host of its own (below). A screen built without `AMScene`, or a window of the app's own, puts its own. It's a `Box` with `propagateMinConstraints`, so the content is laid out exactly as the host is; the message is drawn in a `matchParentSize` layer over it, takes no space from it, and lets touches outside the message through. It provides itself to its content through an internal `CompositionLocal` (`LocalAMBannerHost`, `LocalAMToastHost`, null with none above), so a call posts to the **nearest** host.
- **The topmost window shows them.** A sheet is a window over its screen, so a message drawn in the screen's host would lie under it. A sheet's hosts are `BannerHost` / `ToastHost` with `overScreen = true`: each is made with the host above it (the screen's, from the local) as `below`, sharing its root, and holds itself up over the root (`OverScreen`: `open()` while the sheet's content is composed, `close()` when it leaves). `TransientHost.current` is then the most recent posting made to **any** host of the root (the screen's or a sheet's, compared by the root's posting order), shown by the topmost open window's host only; the others show none. So while a sheet is up, a toast or banner posted from the screen under it (a scene's `overlays`, a root) or from inside the sheet shows over the sheet; a second sheet over the first takes over from it; and when the sheet goes, a message still up shows in the screen's host again, with its full time. Public `AMBannerHost` and `AMToastHost` are always roots.
- **A sheet's toasts** show at the sheet's bottom in its toast host (the sheet's column, clearance 0), over its content, above the navigation bar and the keyboard. **A sheet's banners** show in a window of their own at the top of the screen (`BannerWindow`): a `Popup` at the sheet window's top start (`WindowTop`, `IntOffset.Zero`; the sheet's window is full screen) with `PopupProperties(focusable = false, dismissOnBackPress = false, dismissOnClickOutside = false, clippingEnabled = false)`, composed while the banner's `Transition` has a posting as its current or target state (so it stays through the slide away). The popup takes the sheet window's `safeDrawing` insets (top and sides) as fixed `WindowInsets`, read outside it, and spans only the card's band, so the sheet keeps every touch below it; its band fills the window (`fitted`): opaque behind the status bar, clear at the card's bottom. Inside, the banner starts from a window's fresh context (`ProvideOverlayWindowLocals`, `Overlays.md`), since the popup lies over the screen, not on the sheet: lying on the page with no art to sample, so in a frosted app the card and the band are frost over the page color, opaque, never the sheet's tint. It never takes focus, so a field in the sheet keeps the keyboard.
- **The call** (`AMBanner(item, onDismissRequest, onClick)`, `AMToast(item, onDismissRequest)`): state is hoisted, the caller holds an `Item?`. The call draws nothing where it is; it posts its item to the nearest host while the item is non-null and the call is composed. **With no host above it, reading the local fails at once** (an error naming the missing host), so a forgotten host never shows up as a silent no-op.
- **Asking to go.** The host calls `onDismissRequest` when the message's time is up, and on the user's dismissal (a swipe, a tap, a screen reader's dismiss action). The caller sets its item back to null there; until it does, the message stays (a toast whose time is up is already gone from the screen).
- **One at a time.** A host shows the most recent posting. A caller that posts a new item replaces its own posting, the new one made the most recent; a posting covered by a newer caller's shows again if it's still up when the newer one goes, with its full time.
- **Items compare by identity** (`@Immutable` classes, no `equals`), so posting a new item with the same text shows it afresh and restarts its time.
- **Time.** Each item has a `duration` (banner 4 s, toast 2 s), which the host stretches to the user's accessibility timeout (Accessibility → Time to take action) through `LocalAccessibilityManager`'s `calculateRecommendedTimeoutMillis`, the way Material's snackbar host does. The time runs while the posting is the one shown.
- **Not overlays.** Banners and toasts aren't modal and don't report through `ReportOverlayUp`; the scene's floating action button stays. A banner is at the top, clear of it; a scene with `floatingActions` raises its toasts above the button's resting place (below).

The shared plumbing (internal, in `Banner.kt`): `TransientHost<T>(below = null)` keeps a snapshot list of `TransientPosting(caller, item, order)` (the order from its root's counter) and, on a root, the snapshot list of windows open over it; `current` is described above; `post(caller, item)` removes the caller's posting and appends the new one (null withdraws). `PostTransient` remembers a `TransientCaller` per call site, updates its callbacks in a `SideEffect` (`actionable`, whether there's an `onClick`, is snapshot state), and posts in a `DisposableEffect` keyed on the host and the item, withdrawing on dispose; `open()` and `close()` (from `OverScreen`) add and remove a window over the root.

## `AMBanner` (`Banner.kt`)

```kotlin
var banner by remember { mutableStateOf<AMBannerItem?>(null) }
AMButton("Save", onClick = { save(); banner = AMBannerItem("Changes saved", message = "Your profile is up to date.", style = AMSemantic.Success) })
AMBanner(banner, onDismissRequest = { banner = null })
```

- **`AMBannerItem(title, message = null, style = AMSemantic.Info, duration = 4.seconds)`**. The glyph is the style's (`AMSemantic.icon`, filled, tinted `AMSemantic.color`); there's no other glyph.
- **Look.** The floating surface in `shapes.large`: `amElevatedSurface(shape, alwaysOutlined = true)` at `Low`, in the app's surface setting: solid with the selection-ring hairline in both modes in a solid app (as the floating action button and the remote's tiles), frosted with the frosted edge in a frosted one (over the art under it, or frost over the page color with none). Inside, `spacing.md` all round: a top-aligned row, `spacing.md` apart, of the glyph (24 dp) and a column of the title (`bodyLarge`, `onSurface`) over the message (`bodyMedium`, `onSurfaceVariant`), 2 dp apart. Full width, inset `spacing.lg` at the sides and `spacing.sm` under the status bar (`WindowInsets.safeDrawing`, top and horizontal sides, so the display cutout too).
- **The band** (private `bannerScrim`). Behind the card, from the window's top edge, 220 dp tall: a surface in the app's setting, opaque to 20 %, then fading to clear. It backs the status bar while the banner is up, so the card reads as part of the screen's top and the status bar stays legible. It draws only, taking no touches. The surface is `amControlSurface(RectangleShape, AMElevation.None, outline = false)` (`Foundations.md`): `Surface.primary` in a solid app; in a frosted app frost over the art of `LocalAMBackdrop` under the band, or frost over the page color (`#FAFAFC` / `#0A0A0B`) with none. It lies on the page, so it isn't the tint. The fade is an alpha mask: the band draws in an offscreen layer (`graphicsLayer { compositingStrategy = Offscreen }`), then `drawWithContent` draws a vertical gradient from black to clear over it with `BlendMode.DstIn`, so the surface keeps the mask's alpha. **A screen host lies on art**: the screen's banner layer (band and card, `ScreenBannerLayer`) gets `LocalAMBackdrop.current ?: sceneBackdrops?.showing`, the backdrop around the host or, in an `AMScene`'s roots form with none, the art the showing root draws (`Navigation.md`), provided around the layer only, never around the content.
- **Motion** (Material's motion scheme; Remove animations makes it instant), on one `updateTransition` of the host's current posting: the band (`Transition.AnimatedVisibility`) fades in on `defaultEffectsSpec` and out on `fastEffectsSpec`. The card is a `Transition.AnimatedContent` keyed by the caller: it slides down from above the window (its full height, insets included) with `defaultSpatialSpec` plus a fade, and leaves back up with `fastSpatialSpec`; a new item from the same caller changes the card in place, a different caller's slides the old out and the new in. No size animation.
- **Swipe up.** `Modifier.draggable` (vertical) moves the card 1:1 through an offset, clamped so it only goes up. On release it dismisses if dragged more than 30 dp or flung up faster than 125 dp/s (the removal then slides on from where the finger left it); otherwise it settles back with `fastSpatialSpec`, carrying the fling's velocity. A new posting starts at rest.
- **Tap.** With `onClick`, the card is `clickable` with `Role.Button` and Material's ripple, clipped to the shape: a tap calls `onDismissRequest`, then `onClick`, so the action can post a follow-up banner. Without it, a tap only dismisses (a tap gesture with no semantics, so the card doesn't read as a button). The swipe and the timer never call `onClick`.
- **Accessibility.** The card merges into one element with a **polite live region**, so TalkBack reads it once when it appears (or changes) without interrupting: the role's `severityLabel` as the glyph's description ("Success", "Warning", "Error"; none for `Info`), the title, then the message. It carries a `dismiss` semantics action. An actionable banner is one button. The timeout counts icons and, when actionable, controls.

## `AMToast` (`Toast.kt`)

```kotlin
var toast by remember { mutableStateOf<AMToastItem?>(null) }
AMButton("Copy link", onClick = { copy(); toast = AMToastItem("Link copied") })
AMToast(toast, onDismissRequest = { toast = null })
```

- **`AMToastItem(text, duration = 2.seconds)`**: neutral, no role, no glyph, no action. Status news with a role is a banner.
- **Material's snackbar, its container in the app's setting.** The host owns a `SnackbarHostState` and a Material `SnackbarHost` that draws Material's `Snackbar` (`Snackbar(data)` in a solid app, its content form in a frosted one, below): Material's shape, shadow, padding and motion (fade and scale), its polite live region and its dismiss action. Its colors follow the app's surface setting by container color alone (internal `frostedContainerColor()`, `Foundations.md`): in a solid app Material's own (inverse surface, inverse on-surface); in a frosted app the container is frost over the page color, opaque (`#FAFAFC` / `#0A0A0B`, since the snackbar samples no art), with `onSurface` text, in a sheet's toast host too: a toast is never the tint, which has no blur and would let the sheet's content under it show through. There it also takes the frosted edge, `AMTheme.Frosted.edge` at 0.5 dp on its own shape: private `FrostedSnackbar` draws Material's content form, `Snackbar(modifier = Modifier.padding(12.dp).amHairline(SnackbarDefaults.shape, AMTheme.Frosted.edge), shape, containerColor, contentColor) { Text(message) }`, since the data form pads the modifier it's given by 12 dp before the snackbar, where an edge passed through it would sit; the 12 dp margin (`SnackbarMargin`) places it as the data form does. The toast has no action or dismiss button, so the text is all either form shows. `ToastVisuals` gives the text, no action label, no dismiss button and `SnackbarDuration.Indefinite`, since the toast host does the timing.
- **Placement.** The snackbar host sits at the bottom center of the host's layer, padded by `WindowInsets.safeDrawing` (bottom and horizontal sides), so it's above the navigation bar, and above the keyboard while it's open, then by the internal `ToastHost`'s `bottomClearance`: 0 for `AMToastHost` and a sheet, and in an `AMScene` with `floatingActions` the button's resting top (`floatingActionButtonTop()`, `Navigation.md`), so the toast shows just above the button. The clearance follows the resting place, not a button the user has moved.
- **Timing.** A `LaunchedEffect` keyed on the current posting calls `showSnackbar` inside `withTimeoutOrNull(timeout)`, then calls `onDismissRequest`: the snackbar comes down when the time is up (the cancelled call removes it) or when a screen reader dismisses it, and the toast asks to go either way. A newer posting, or none, cancels the effect, which takes the snackbar down without asking.

## `AMLoadingOverlay` (`LoadingOverlay.kt`)

```kotlin
var saving by remember { mutableStateOf(false) }
AMButton("Save", onClick = { scope.launch { saving = true; save(); saving = false } })
AMLoadingOverlay(saving, message = "Saving…")
```

- **`AMLoadingOverlay(visible, message = null)`**: a window, the Android way. While `visible`, a Compose `Dialog` with `DialogProperties(dismissOnBackPress = false, dismissOnClickOutside = false, usePlatformDefaultWidth = false)`: the platform's dialog dim behind it. `onDismissRequest` does nothing; a tap outside does nothing; the dialog's back callback consumes back (and predictive back), so nothing under it moves. Only the caller ends it, by turning `visible` false.
- **Its own window's context.** The dialog's content starts inside `ProvideOverlayWindowLocals` (`Overlays.md`), as every overlay window's does: no `AMBackdrop` from the screen under it (a window can't sample another window's art), no art tone, enabled, elevated, lying on the page, `onSurface` content; the app's surface setting carries in.
- **The card.** The dialog's content fills the window (so the card's shadow has room on every side) and centers a full-width card, inset `spacing.xl` at the sides: `Modifier.amCard(padding = spacing.lg)`, in the app's setting: solid in a solid app; in a frosted app frost over the page color, opaque, since the window has no art to sample. It holds Material's indeterminate `CircularProgressIndicator` over the message (`bodyMedium`, `onSurfaceVariant`, centered), `spacing.md` apart. A null message shows "Loading", so the indicator always has a caption. The card merges into one element; the dialog is a modal window, so TalkBack stays inside it.
- **Reports itself.** It calls `ReportOverlayUp(visible)`, so a scene's floating action button fades while it's up.

## `AMEmptyState` (`EmptyState.kt`)

```kotlin
AMEmptyState(
    painterResource(R.drawable.ic_inbox), "No messages",
    description = "New messages will appear here.",
    action = AMEmptyStateAction("Compose", painterResource(R.drawable.ic_edit_square)) { compose() },
)
AMEmptyState(painterResource(R.drawable.ic_group), "No contacts", description = "Add people to start a conversation.") {
    AMButton("Add contact", onClick = ::addContact, style = AMButtonStyle.Primary())
    AMButton("Import contacts", onClick = ::importContacts, style = AMButtonStyle.Ghost)
}
```

- **Two forms.** String: `AMEmptyState(icon, title, modifier, description: String? = null, action: AMEmptyStateAction? = null)`; the one action shows as an `AMButton` forced to `AMButtonStyle.Primary()`, its glyph before its label. Slot: `AMEmptyState(icon, title, modifier, description, actions: ColumnScope slot)`, for several buttons or other styles; it doesn't restyle them (each takes its own `style`, or `LocalAMButtonStyle`). Both go through private `EmptyStateLayout`, which takes the actions as a nullable slot. The slot form's `actions` is required, so the two never overlap.
- **`AMEmptyStateAction(label, icon: Painter? = null, onClick)`**: an `@Immutable` action payload, like `AMSwipeAction`.
- **Look.** A column filling the width, padded `spacing.xl` above and below (no side padding: the caller places it), everything centered: the glyph at 48 dp in `onSurfaceVariant`, `spacing.md`, the title (`titleLarge`, `onSurface`), `spacing.xs`, the description (`bodyMedium`, `onSurfaceVariant`), all text centered; then `spacing.lg` and the actions in a centered column `spacing.sm` apart.
- **On the page, never on a card.** It draws no surface: the glyph and text lie on whatever is behind them (the page color, the app's backdrop, a search window), and only its buttons float. Put it where the content would have been, not in a card.
- **On art** (an art tone around it, `LocalAMArtTone` non-null) the glyph, title and description are art text for the tone: the title `amArtText()`, the glyph and description `amArtText(secondary = true)` (the tone's fixed ink with its soft shadow, `DataDisplay.md`). The buttons keep their own looks: filled ones are surfaces, a ghost one reads the tone itself (`Actions.md`).
- **Accessibility.** The glyph is decorative (no description). The glyph, title and description merge into one element whose title carries heading semantics, so TalkBack reads the title and description together as a heading; each button is its own element.

## `AMSkeleton` and `Modifier.amShimmer()` (`Skeleton.kt`)

```kotlin
Row(horizontalArrangement = Arrangement.spacedBy(12.dp), verticalAlignment = Alignment.CenterVertically) {
    AMSkeleton.Circle()
    AMSkeleton.Text(Modifier.weight(1f), lines = 2)
}
AMSkeleton.Rect(height = 160.dp, shape = MaterialTheme.shapes.medium)
AMSectionHeader { if (loading) AMSkeleton.Text(month.title) else Text(month.title) }
```

- **`AMSkeleton`** is an object holding the placeholder shapes, each a `Box` filled with the color scheme's `surfaceContainerHighest` in its shape and wearing `amShimmer`. A loading state is laid out from these shapes the way the content will sit, then swapped for the content.
  - `Rect(modifier, height = 14.dp, shape = shapes.small)`: fills the width it's given (`modifier` first, then `fillMaxWidth`), so the caller sizes it with `width`, `fillMaxWidth(fraction)` or a weight.
  - `Circle(modifier, diameter = 40.dp)`: an avatar's or glyph's place, `CircleShape`.
  - `Text(modifier, lines = 3, lineHeight = 12.dp, spacing = spacing.sm)`: full-width rounded bars (`CircleShape`), the last one 60 % as wide when there's more than one, so it reads as a paragraph. The shimmer sits on the whole column, so one band sweeps every line together.
  - **`Text(text, modifier, style = LocalTextStyle.current, minLines = 1, maxLines = Int.MAX_VALUE)`**, the text in hand: the loading layout's place for a real text (a heading, a name, a count). It's Compose's `BasicText` with that text, style and line limits (`TextOverflow.Clip`), so it takes the text's exact size and line height and wraps the same way, and swapping the real `Text` in moves nothing. A `drawWithContent` that never draws the glyphs draws instead, from the `TextLayoutResult` (`onTextLayout`, held in state), one rounded bar per line (`drawTextBars`): from the line's left to its right (`getLineLeft` / `getLineRight`, so as wide as its words), the line's height less 15 % above and below (`TextBarInset`), fully rounded, in `surfaceContainerHighest`. Lines `minLines` reserves past the text's own keep their room with no bar. It wears `amShimmer` and `clearAndSetSemantics {}`, so TalkBack hears nothing. The default style is the `LocalTextStyle` a container provides (a section header's slot, a list item's headline), so it matches a `Text` in the same place.
  - They take no input and carry no semantics.
- **`Modifier.amShimmer()`**: `graphicsLayer(compositingStrategy = Offscreen)` then private `ShimmerNode` (a `DrawModifierNode`). The node draws the content, then a white band over it with `BlendMode.SrcAtop`, so the band lights only the pixels the content drew (its shapes, not the gaps); the offscreen layer isolates the blend, cuts the content to its bounds (so it goes on placeholders inside a card, never on a card with a shadow) and is the layer the node re-records each frame, so nothing recomposes and nothing around it redraws.
- **The band**: a horizontal gradient, clear to white at 0.3 to clear, `max(40 % of the width, 60 dp)` wide; it enters fully off the start and leaves fully off the end, so the wrap never shows. The brush is cached per band width. The recipe (cycle, band, highlight) is private constants in `Skeleton.kt`, not theme values, so a loading rhythm doesn't drift when an app re-tunes its theme.
- **Motion.** The component's own: a linear sweep every 1.2 s, looping, a fixed loop like Material's own indeterminate indicators (the motion scheme's springs don't loop). The node launches it on attach in its `coroutineScope` (cancelled on detach) and reads each frame with `withInfiniteAnimationFrameNanos`; the phase is the frame time modulo the cycle, so every shimmer on screen sweeps in step. It reads `MotionDurationScale` from its coroutine context: the cycle stretches with the animator duration scale, and at 0 (**Remove animations**) the band goes away and the node waits (`snapshotFlow { scaleFactor }.first { it > 0 }`) until animations return, drawing the content still.

## `AMProgressView` (`ProgressView.kt`)

```kotlin
AMProgressView("Checking for new mail")                                          // indeterminate spinner in a card
AMProgressView("Uploading", progress = { 0.6f }, valueLabel = "60%", style = AMProgressViewStyle.Bar)
AMProgressView("Downloading", progress = { 0.4f }, style = AMProgressViewStyle.Glyph)    // a row's trailing glyph, spoken only
```

- `AMProgressView(label, modifier, progress: (() -> Float)? = null, valueLabel: String? = null, style = Spinner())`. `progress` is Material's deferred read (0 to 1); null runs the indicator indeterminate. The `label` is required: progress always says what's happening, aloud when it isn't shown.
- **`AMProgressViewStyle`**, sealed: `Spinner(card = true)` (an `@Immutable` class with value equality), `Glyph` and `Bar` (`data object`s).
- **Spinner**: Material's `CircularProgressIndicator` (determinate or indeterminate) over the label as a caption (`bodySmall`, `AMTheme.secondaryText`, centered), `spacing.md` apart, centered in a column. With `card` (the default), the column fills the width in `amCard(padding = PaddingValues(horizontal = xl, vertical = lg))`, the way a loading view shows it on the page, in the app's surface setting (solid in a solid app; in a frosted app frosted on the backdrop, frost over the page color with no art under it, and the tint on a sheet, `Layout.md`); inside another card that card lies flat by the nesting rule. `card = false` places it inline, for a card or strip that already holds it. It shows no value label.
- **Glyph**: Material's `CircularProgressIndicator` (determinate or indeterminate) with no caption, in the place a row's trailing glyph takes (a download, a refresh): a 24 dp glyph's box and no touch target, since it takes no input, so at a row's end it lines up with the other rows' trailing content as a trailing icon does in Material's list item; the ring 20 dp (a glyph's live area, inset 2 dp) and 2 dp thick, Material's 40 dp / 4 dp at half the size. The label is its spoken name (`contentDescription` on the box, merged with the indicator's progress); it shows no value label.
- **Bar**: on the row recipe and the flat-row surface (`amFlatSurface` then `amRowPadding`: a strip in the app's setting where it stands on its own, the floating surface's color in a solid app and frosted, or the tint on a sheet, in a frosted one; nothing inside a card; `Layout.md`), its lines lying on the strip or card (`ProvideAMOnSurface` inside the bar's column, so the strip itself stands where the bar is placed), a column `spacing.sm` apart of a row (the label in `bodyLarge` / `onSurface`, weighted, up to two lines and ellipsized (`BarLabelMaxLines`), and the value label in `bodyMedium` / `AMTheme.secondaryText` (the frosted secondary on frost) at the end, one line, `spacing.md` from it, both aligned by baseline) over Material's `LinearProgressIndicator`, full width. Bars stack in a card with `AMDivider(inset = spacing.lg)` between, like rows.
- **The bar is a row for TalkBack.** It claims a row container's actions (`claimRowActions()`, `Lists.md`) onto its own merged node and provides `LocalAMRowActions` null inside, so in an `AMSwipeableRow` or a reorderable list the swipe and move actions sit on the stop that reads the label, and the container has no stop of its own (tested: `RowSemanticsTest`).
- **Native.** The indicators keep Material's size (the glyph's ring excepted), colors (`primary` on its track), gap and stop indicator, and its indeterminate motion. Each view merges into one TalkBack element: the label, the value label and the indicator's progress.

## `AMPullToRefreshBox` (`PullToRefresh.kt`)

```kotlin
val scrollBehavior = TopAppBarDefaults.exitUntilCollapsedScrollBehavior()
Scaffold(topBar = { AMPageHeader("Feed", scrollBehavior = scrollBehavior) }) { padding ->     // no nestedScroll on the Scaffold
    AMPullToRefreshBox(refreshing, onRefresh = ::refresh, Modifier.fillMaxSize().padding(top = padding.calculateTopPadding()), scrollBehavior = scrollBehavior) {
        LazyColumn(Modifier.fillMaxSize()) { … }
    }
}
```

- `AMPullToRefreshBox(isRefreshing, onRefresh, modifier, scrollBehavior: TopAppBarScrollBehavior? = null, state = rememberPullToRefreshState(), enabled = true, content: BoxScope.() -> Unit)`. `isRefreshing` is hoisted: a release past the threshold calls `onRefresh`, the indicator spins while `isRefreshing` is true and leaves when it turns false. `enabled` (resolved with `LocalAMEnabled`) gates the pull only.
- **Native.** A `Box` with Material's `Modifier.pullToRefresh` (its state, threshold and release) and `PullToRefreshDefaults.Indicator` at `TopCenter`, Material's colors and motion; the content comes first, the indicator over it.
- **It owns the header's connection.** With a `scrollBehavior` (the `AMPageHeader`'s), the box chains `nestedScroll(scrollBehavior.nestedScrollConnection)` after `pullToRefresh`, so the header's connection sits nearer the content than the pull. Compose hands a drag's first share outermost first and its leftover innermost first, so: down, the content scrolls to its top, then the leftover reopens a collapsed header, and only a header fully open lets the pull have it; up, a pulled indicator goes away first, then the header collapses, then the content scrolls. The connection goes on the box only: also on the `Scaffold`, it would collapse the header ahead of the pull. Without a `scrollBehavior` it's Material's pull to refresh as is.
- **The indicator sits under the header.** Placed in the `Scaffold`'s content, padded by the top bar's height, the box starts at the header's bottom edge, and Material's indicator comes out from under it.
- Used by the Social scene's feed (`SceneSocial.md`); checked on the emulator, with no test of its own.
